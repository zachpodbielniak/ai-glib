#+TITLE: Changelog

All notable changes to ai-glib. The format follows [[https://keepachangelog.com/en/1.1.0/][Keep a Changelog]]
and the project uses [[https://semver.org/][semantic versioning]]. Until 1.0.0, a minor
release may change the API.

* 0.15.0 - 2026-11-22

** Added
- =AiComfyuiClient=: a self-hosted [[https://github.com/comfyanonymous/ComfyUI][ComfyUI]] server as an =AiMediaGenerator=, over ComfyUI's own HTTP API (=/prompt=, =/history=, =/queue=, =/view=, =/upload/image=; default =http://127.0.0.1:8188=). It runs the operator's own workflow, exported in API format and set with =ai_comfyui_client_set_workflow()= or per request as a =workflow= parameter, and fills ={{prompt}}=, ={{negative_prompt}}=, ={{seed}}= and ={{image}}= in the nodes' string inputs by walking the parsed graph, so a prompt with quotes or braces stays one string value; a whole-input ={{seed}}= becomes a number, and an absent seed is random. Poll tells queued from running through =/queue= and reports ComfyUI's own failure text; results are =/view= URLs in node order; downloads are refused unless under the base URL; responses are read against a size ceiling; the estimate is 0 (self-hosted, no charge); there is no cancel, because ComfyUI's interrupt and delete cannot say whether they worked. =ai_comfyui_client_upload_async()= uploads a reference image, and =ai_comfyui_client_set_token()= sends a bearer token to an authenticating proxy, never logged and redacted from every error. See =docs/providers/comfyui.org=.

** Fixed
- =AiHiggsfieldClient= built its messages and sessions with bare libsoup constructors, so =make test= failed at =check-http-constructors= on 0.14.0. They now go through =ai-http-redirect-private.h=: API requests and the presigned upload =PUT= are declared as carrying a credential (never redirected), result downloads as public URLs.
* 0.14.0 - 2026-11-21

** Added
- =AiMediaGenerator=: an interface for media generated as a queued job.
  Submit returns a job id, poll returns an =AiMediaJob= (state, the
  service's own status word, result URLs, cost in micro-USD, expiry),
  download returns the bytes; estimate and cancel are optional and answer
  =AI_ERROR_NOT_SUPPORTED= when absent. =ai_media_generator_wait_async()=
  polls with backoff and jitter (2 s to 10 s by default), retries transient
  failures, honours a deadline and a =GCancellable=, and completes on the
  caller's thread-default context. =AiMediaRequest= carries a model, a
  prompt and an open JSON object of parameters, plus an idempotency key
  that survives a resubmit, a webhook URL and a retention. See
  =docs/api-reference/ai-media-generator.org=.
- =AiHiggsfieldClient=: Higgsfield's hosted image and video API
  (=https://api.higgsfield.ai=, =Authorization: Key <id>:<secret>=) as an
  =AiMediaGenerator=, with cost estimates, cancellation and
  =ai_higgsfield_client_upload_async()= for input files. Credentials are
  set explicitly, never read from the environment, never sent to
  download or upload storage, and redacted from every error. See
  =docs/providers/higgsfield.org= for the verified API facts and the
  service's terms.
* 0.13.0 - 2026-11-20

Room mode, chiming in and speaker naming for a voice device shared by a room (Forgejo #18, from Ben Doty's branch, finished and hardened). See =docs/voice.org=.

** Added
- Room mode: an utterance is a turn only when it is said to the assistant (by name, or a sound-alike in a name's place); everything else is heard and given to the next turn, bounded by =room-history-lines=, =-chars= and =-age-ms=, optionally with a "[Present: ...]" roster.
- Chiming in: a relevance judge scores unaddressed talk and the assistant speaks up at =chime-in-threshold=; one score in flight, redone when stale rather than cancelled, with debounce, robust answer parsing and back-off after failures. Every score is in the transcript.
- Speaker naming by voiceprint: in process with ONNX Runtime (=AiOnnxSpeakerEmbedder=; TitaNet, wespeaker and 3D-Speaker exports, front-end read from the model's metadata, Kaldi and NeMo filterbanks in plain C) or through a service (=AiHttpSpeakerEmbedder=). Guests numbered in the order heard, a guest cap, a naming deadline, and "stop" or "mute" never followed by an answer to something said before them.
- =ai-voiceprint-server=, a model behind the HTTP protocol, and =contrib/ai-voiceprint-server.service=. Built only with onnxruntime (optional; =HAVE_ONNXRUNTIME=0= opts out).
- Promoting a guest to a lasting name by voice ("Ada, guest two is Kim"), never over an enrolled name; =AiVoiceSession::allow-promotion= can veto it.
- =ai-call=: =--list-voiceprints=, =--rename OLD:NEW=, =--forget NAME=; enrolment refuses under three seconds of speech and warns about clipping and about voices the model confuses; =speaker-backend=, =speaker-model=, =speaker-frontend=, =speaker-threads=, =speaker-timeout-ms=, =max-guests=, =min-guest-ms=, =name-memory-ms=, =naming-timeout-ms=, =promoted-message=, =promotion-refused-message=, =relevance-debounce-ms=, =relevance-max-tokens=, =room-history-*= and =room-roster=; =speaker= and =promotion= transcript records.
- Public interfaces with subclassable defaults: =AiVoiceprint=, =AiSpeakerMatch=, =AiSpeakerEmbedder=, =AiVoiceprintStore= (=AiFileVoiceprintStore=, =AiMemoryVoiceprintStore=), =AiVoiceprintIdentifier= (derivable), =AiAddressDetector= (=AiNameAddressDetector=), =AiRelevanceJudge= (=AiProviderRelevanceJudge=) and =AiVoiceRoom=. =AiVoiceSession= gains =room=, =address-detector=, =relevance-judge=, =relevance-debounce-ms=, =naming-timeout-ms=, =name-memory-ms= and the =speaker-named=, =allow-promotion= and =guest-promoted= signals.
- Tests: =test-voice-room=, =test-voice-onnx=, and much wider =test-voice-speaker=, =test-voice-session= and =test-voice-matrix=.

** Changed
- =AiVoiceSession= is derivable (it was final), with class handlers for its signals.
- =AiSpeakerIdentifier.identify_finish= returns an =AiSpeakerMatch= instead of a name and score. This interface is new in this release, but an implementation written against the #18 branch must be updated.
- The pkg-config file requires GLib 2.70, which libsoup 3 already did, and lists onnxruntime in =Requires.private= when it is used.

** Fixed
- A cancelled =ai_tool_executor_run_async()= returns as soon as the cancel reaches it instead of waiting on a slow provider, and stops forwarding that request's stream events (#17).
- A finished background agent's result is spoken without the caller asking for it.
- Voiceprint files are 0600 in a 0700 directory, written atomically, and never read through a symlink, from another user, oversized or misnamed; a voiceprint vector that is non-finite or all zero is refused.

* 0.12.1 - 2026-11-15

** Fixed
- The "no credential across a redirect" rule from 0.11.0 now covers every
  HTTP request. 0.11.0 guarded the =AiClient= session, Bing, Brave,
  libresearch and =ai-call=; 34 =soup_message_new*()= calls and 14
  =soup_session_new*()= calls still built messages and sessions nobody had
  decided for. Unguarded until now: the SystemOne decision session (whose
  messages already refused redirects), the HTTP synthesizer and websocket
  recognizer (followed anywhere; now same origin), DuckDuckGo (followed
  anywhere; now same origin), the generated-image and video downloads and
  =web_fetch= (still followed anywhere, as public URLs, but refused once a
  credential header is on them). Provider requests are now declared
  credentialed before any header is set, from what the provider's own
  =add_auth_headers()= attaches, instead of being inferred when the session
  queues them; a keyless provider (Ollama) keeps its same-origin redirects.
  A retried image or video request keeps the first attempt's declaration.

** Added
- Private constructors in =core/ai-http-redirect-private.h=:
  =ai_http_message_new()=, =ai_http_message_new_from_uri()= (with
  =AiHttpCredentials=: =AI_HTTP_CARRIES_CREDENTIALS=, the zero value,
  =AI_HTTP_NO_CREDENTIALS=, =AI_HTTP_PUBLIC_URL=) and
  =ai_http_session_new()=; =ai_client_http_credentials()= in the new
  private =core/ai-client-private.h=. Not installed, not in the GIR.
- =tests/check-http-constructors.sh=, run by =make test= (and =make
  check-http-constructors=): fails on a bare =soup_message_new*()= or
  =soup_session_new*()= in =src/=, =bin/= or =gui/= outside the helper,
  with comments and string literals blanked first; =--self-test= proves it
  catches nine probes (including ones behind a ="*/*"= string and a
  comment) and passes decoys. On 0.12.0 it reports all 48 sites.
- Tests in =tests/test-http-redirect.c=: each declaration end to end, a
  key added to a public-URL request after construction, the guarded
  session, every provider's declared credentials (and the OpenAI-compatible
  client's), a generated image following its CDN hop, DuckDuckGo staying
  on its origin.

* 0.12.0 - 2026-11-14

** Added
- =AiAcpClient= (provider type =AI_PROVIDER_ACP=, string ="acp"=, aliases
  ="acp-agent"= / ="acp_agent"=): any program that speaks the Agent Client
  Protocol (v1, JSON-RPC over stdio) is a CLI provider, started from its
  command line (=command= property, shell-style split with no shell, or
  =$AI_ACP_COMMAND=). One process per turn: =initialize=, =session/new=
  (or =session/load= for a persisted session the agent can load, falling
  back to a new session when the load is refused), =session/prompt=.
  =session/update= text, thought, tool calls (=acp_<kind>=, with matching
  tool styles), plans and USD cost become =AiEvent=; =stopReason= becomes
  the stop reason (=max_tokens= and =max_turn_requests= ->
  =MAX_TOKENS=, =refusal= -> =CONTENT_FILTER=). Permission requests are
  answered by option kind under =skip-permissions= (allow) or not
  (reject). =fs/read_text_file= (and, with =skip-permissions=,
  =fs/write_text_file=) are served inside the working directory, symlinks
  resolved; terminals are never offered. A cancel sends =session/cancel=
  and gives the agent =shutdown-timeout-ms= (5 s) before it is killed; the
  same grace bounds the exit after an answer, which is kept. Errors are
  classified through the shared limit table, ACP's =-32000= as
  =AI_ERROR_INVALID_API_KEY=. MCP servers from an =AI_ENDPOINT_KIND_MCP_CONFIG=
  endpoint go to the session as ACP =McpServer= entries. =can_steer= and
  =searches_tools= are FALSE. Wired into =ai -p acp=, the provider factory,
  =ai_simple= and config files. See =docs/providers/acp.org=. Tested
  against a scripted fake agent only.
- =ai_cli_steer_set_protocol_input()= (private): a CLI whose protocol
  answers requests mid-turn keeps stdin open as an =AiCliSteerChannel=
  without becoming steerable.

** Fixed
- =ai --dry-run= crashed when a CLI provider's =build_argv= refused its
  settings (it dereferenced the %NULL argv); it now says so and exits 1.
- =AiMcpHost= read =mcp-config-path= from every provider that takes the
  Claude-schema MCP dialect; it is a claude-code / claude-tmux property,
  so a new consumer of that dialect (=AiAcpClient=) aborted the bind. It
  is now read only where it exists.

* 0.11.0 - 2026-11-14

** Added
- =AiSteerable=: words into a running turn. =ai_steerable_can_steer()= is a
  class datum every client answers; =ai_steerable_steer_async()= /
  =_finish()= return =AI_STEER_DELIVERED=, =AI_STEER_REFUSED= (with an
  =AI_STEER_ERROR=) or =AI_STEER_INDETERMINATE=, which counts as
  delivered. =ai_steerable_dup_turn_id()= is the handle a caller holds so a
  steer cannot land in a later turn. See =docs/steering.org=.
- =AiClaudeCodeClient:steerable= (default off): a streamed turn takes its
  prompt as a stream-json user event and keeps stdin open until the
  =result= line, and a steer is another user event acknowledged by its
  =--replay-user-messages= echo.
- =AiClaudeTmuxClient= steers by typing into the busy TUI; a turn no longer
  ends while a steered line is still queued in claude.
- =AiToolExecutor= is steerable: words are spliced in at the top of the
  next round, after the whole tool batch, alongside the background-agent
  notice.
- =AiCodexCliClient:transport= (="exec"= by default, unchanged) and
  ="app-server"=: drives =codex app-server= (JSON-RPC over stdio:
  =initialize=, =thread/start= or =thread/resume= by session id,
  =turn/start=) and translates its notifications into =AiEvent= -- real
  text deltas, tool items under exec's names, usage, failures through the
  same limit table plus =codexErrorInfo=. Approval requests are answered
  as exec's flags decide them. On app-server =ai_steerable_can_steer()= is
  %TRUE and a steer is =turn/steer= with the expected turn id: a result is
  =DELIVERED=, a refusal (=NoActiveTurn=, =ExpectedTurnMismatch=, a
  non-steerable turn) =REFUSED=, an internal error or no answer within
  =AiCodexCliClient:steer-timeout-ms= (10 s) =INDETERMINATE=. Built from
  openai/codex =rust-v0.169.0='s published protocol and tested against a
  scripted fake server only; =examples/steer-codex-app-server= checks it
  against a real codex. =ai_codex_cli_client_get_transport()= /
  =_set_transport()=, =AI_CODEX_CLI_TRANSPORT_EXEC= /
  =AI_CODEX_CLI_TRANSPORT_APP_SERVER=.
- =AiSteerableInterface.is_steerable=: an optional per-instance answer
  for a class with =can_steer= %TRUE whose instances differ (codex, by
  transport). =ai_steerable_can_steer()=, =_dup_turn_id()= and
  =_steer_async()= consult it.
- Every CLI wrapper classifies its usage limit, rate limit and sign-out:
  codex, grok-build, opencode, cursor and antigravity map their own words
  to =AI_ERROR_SESSION_LIMIT=, =AI_ERROR_RATE_LIMITED=,
  =AI_ERROR_INVALID_API_KEY= and =AI_ERROR_INSUFFICIENT_QUOTA= instead of
  =AI_ERROR_CLI_EXECUTION=, on the chat, stream and sync paths; a session
  limit has claude-code's shape and notice. =ai_session_limit_parse_reset()=
  reads codex's "Try again at ..." times, more duration forms and
  Retry-After.
- =ai_cli_client_searches_tools()= and =AiCliClientClass.searches_tools=:
  whether a CLI looks its MCP tools up itself (claude-code, claude-tmux,
  grok-build).

** Changed
- The first steerable stream ignores =SIGPIPE= when no handler is
  installed, so a CLI that exits mid-steer cannot kill the caller.
- A streaming CLI run that exits non-zero with nothing on stdout and a
  reason on stderr is an error, not an empty answer (cursor-agent reports
  limits and sign-out that way).

** Fixed
- A request carrying a credential never follows a redirect, not even to
  its own origin: libsoup kept headers such as =x-api-key= and resent a
  307/308 body. A refused redirect is =AI_ERROR_NETWORK_ERROR= naming it.
  Covers every =AiClient=, the Bing and Brave search helpers,
  =AiLibresearchSearch= (whose asynchronous requests were unguarded) and
  =ai-call='s Matrix and JWT requests.
- =/ai-glib/ai-tui/decision/interactive= failed wherever
  =TYPESAFE_API_KEY= was exported: =/decide= without =-p= rightly prefers
  TypeSafe, and the suite's tmux server inherited the developer's key, so
  the test asked api.typesafe.ai instead of its loopback Laya fixture. The
  suite now clears =TYPESAFE_*=, =LAYA_*= and =OLLAMA_*= before starting
  tmux, as the other decision tests do.

* 0.10.2 - 2026-11-07

** Fixed
- =AiCodexCliClient= reports why a turn failed rather than the first
  warning codex printed. An error *item* (codex's non-fatal notice, such as
  "Model metadata for `x` not found") and a top-level =error= no longer end

* 0.10.0 - 2026-11-07

** Added
- =AiLibresearchSearch=: a client for a running libresearch server over
  its REST API. It is an =AiSearchProvider= (=/api/v1/search=) and also
  runs category searches, fetches a page's text (with a Wayback Machine
  fallback), runs LQL queries (=/api/v1/query=), asks for cited research
  answers (=/api/v1/research=) and reads the instance's LQL environment,
  each asynchronously; =ai_libresearch_format_*()= render the documents
  for a model. See =docs/web-search.org=.
- =ai_search_provider_new_default()= picks libresearch first when
  =LIBRESEARCH_URL= is set (=LIBRESEARCH_TOKEN= as its bearer token).
- =web_search= and =web_fetch= in the MCP host catalog; granting
  =web_search= gives the executor the default search provider.
- =ai_mcp_config_load_servers()=, =ai_mcp_config_translate()= and
  =ai_mcp_config_endpoint_for()=: one Claude-schema =.mcp.json= server list
  rendered in the dialect each CLI takes (codex =-c= lines, a grok TOML
  fragment, an opencode config). A server a dialect cannot carry is named,
  never approximated: codex is not given an environment, since it would
  sit in its argv.
- =AiClaudeTmuxClient:settings=: extra Claude settings (a path or JSON)
  merged into the client's own =--settings=; hook arrays are appended per
  event, so a host's =PreToolUse= hook runs beside the readiness hooks.
- Per-request =ai_libresearch_search_*_finish()= functions, so
  introspection pairs each =_async()=.
- =ai_cli_client_set_config_dir()=, =_get_config_dir()= and
  =_supports_config_dir()=, with the class datum
  =AiCliClientClass.config_dir_env= (in the last reserved slot): run a CLI
  under a separate account. claude-code and claude-tmux set
  =CLAUDE_CONFIG_DIR=, codex =CODEX_HOME=, grok =GROK_HOME=, opencode its
  three XDG roots; cursor and antigravity refuse.

** Fixed
- claude-tmux now hands the client's environment to the pane with
  =tmux new-session -e=. The pane's claude is a child of the shared tmux
  server, so nothing set on the client -- an account, an endpoint
  credential -- reached it before.
- claude-tmux looks for transcripts under =$CLAUDE_CONFIG_DIR/projects=
  when that is set, instead of the default account's.
- =AiQuota= no longer shows one account's allowance under another's.
- =ai-tui= asks for the wide-character curses API explicitly.

* 0.9.0 - 2026-10-26

** Added
- =ai benchmark=: run the same work against several providers or models and
  compare latency (nearest-rank p50/p95), accuracy against labelled answers,
  calibration (Brier score, log-loss), error rate and token use. Covers chat
  (optionally streamed, with time to first token), typed decisions (TypeSafe
  Jev, Ollama decision models, Laya), embeddings and image generation.
  Suites are YAML (or JSON); quick mode builds one case from flags. Output as
  a table, YAML, JSON or CSV. =--dry-run= validates a suite and prints the
  call count without calling anything. See =docs/benchmark.org=.
- =AiBenchmark=, =AiBenchmarkTarget=, =AiBenchmarkCase=, =AiBenchmarkSample=
  and =AiBenchmarkSummary= in =src/bench/=, fully introspectable, so ai-tui,
  ai-gui and Emacs can drive the same runner and print the same output.
- =ai_provider_factory_new_decider()=: builds =typesafe=, =jev=, =ollama= or
  =laya= by name. =ai decide= and =/decide= now construct their client
  through it.
- Example suites in =docs/examples/benchmark-*.yaml=.

** Changed
- =ai --set= parses values through a shared private helper
  (=src/core/ai-property-util.h=) that benchmark suites use too, so the two
  cannot drift.

** Fixed
- =ai --set= refuses a number that does not fit the property: =-1= for an
  unsigned property used to wrap to 4294967295, and a value outside the
  property's range made GLib warn (fatal under =G_DEBUG=fatal-warnings=) and
  leave the property unset. Both are now "cannot read ... as a value".

* Versioning

Every pull request that changes behaviour bumps the version in =config.mk=
and adds its entry under a heading for that version at the top of this
file, in the same PR. =make test= fails when the newest heading here does
not match =config.mk= (=make test-version=). The rules, and what counts as
a feature or a fix, are in [[file:docs/contributing.org::*Versioning][docs/contributing.org]].

Tags are the maintainer's, after merge; nothing in the tree pushes one:

#+begin_example
git tag -a v0.4.0 -m "ai-glib 0.4.0"
git push origin v0.4.0
#+end_example

After a tag, =git describe= in every build says =v0.4.0-N-g<commit>=, which
is what =--version= shows.
