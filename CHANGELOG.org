#+TITLE: Changelog

All notable changes to ai-glib. The format follows [[https://keepachangelog.com/en/1.1.0/][Keep a Changelog]]
and the project uses [[https://semver.org/][semantic versioning]]. Until 1.0.0, a minor
release may change the API.

* 0.7.2 - 2026-10-16

** Fixed
- Accepting a directory from the =ai-tui= =@= menu keeps the path
  completer open on the entries inside it.
- Accepting a command or skill inserts a trailing space, so the next
  character is an argument rather than part of the name.

* 0.7.1 - 2026-10-15

** Fixed
- =make install= always installs =ai-gui='s desktop file when the
  client was built, including a later install that does not see
  gtk4 on =pkg-config=. The file is =org.copyleft.AiGlib.Gui.desktop=,
  matching =AI_GUI_APP_ID=, with =StartupWMClass=ai-gui=.

* 0.7.0 - 2026-10-02

** Added
- Project path entry in both dashboards; recent projects remain available after
  disconnected work records are removed. GUI quick-open reuses an already loaded
  conversation for the directory.
- Queued-message editors in GUI and TUI (=Alt+Q=), with full text editing,
  removal, attachment preservation, and paused dispatch while editing.

** Fixed
- Starting from the TUI dashboard creates a worker in the project's tmux session.
  Renaming that session no longer causes duplicate project sessions.
- GUI dashboard groups each project once, using the same projection as the TUI.
- Disconnected dashboard records are pruned under their ownership locks, without
  deleting saved conversations or provider transcripts.
- Tmux window status prefixes are normalized, repairing stacked WORK/DONE names;
  reporters on the same server share a lock across state-directory settings.
- Changing to another project inside tmux opens that project's session instead
  of mixing projects in one session. GUI =/cwd= selects or opens a conversation
  for the directory; new GUI conversations clear inherited native resume flags.

* 0.6.0 - 2026-10-01

** Added
- Live voice sessions. =AiVoiceSession= composes a transport, a speech
  recognizer, a synthesizer and voice activity, and =ai-call= runs one
  over MatrixRTC or on this machine with =--local=. See
  [[file:docs/voice.org][docs/voice.org]].

** Fixed
- The =grep= tool reads regular files only and skips anything over 16 MiB,
  so a FIFO or =/proc= file cannot stall a turn.

* 0.5.0 - 2026-09-28

** Added
- Projects as a first-class thing. =AiProject= groups the work registry
  by repository (worktrees included) with counts, the most urgent status
  and the main checkout, and finds a project by name or by any path in
  it. One name (=ai_project_label_for_path()=) and one order
  (=ai_work_session_compare()=) now serve ai-tui, ai-gui and the CLI. See
  [[file:docs/projects.org][docs/projects.org]].
- =ai project [list]= and =ai project show [NAME|PATH]=, with =--json=.
- ai-tui: the session panel shows the project and branch, the dashboard
  groups sessions under a heading per project, and a worker launched from
  it opens as a window in its project's own tmux session.
- ai-gui: the window subtitle names the project.
- When account usage cannot be read, ai-tui and ai-gui say why instead of
  only "Unavailable". Reset times read "in 2h 41m", "Fri 17:59" or "Nov 5".

** Fixed
- Claude Code account usage always read "Unavailable". It is now read with
  Claude Code's =get_usage= request, which works in any directory, sends
  no prompt and writes no transcript, instead of scraping the =/usage=
  screen, which Claude Code now puts behind a folder-trust prompt.
- ai-gui kept an old session's header handlers connected after switching
  sessions.

* 0.4.0 - 2026-09-27

** Added
- =/loop= and =/goal=: repeating prompts and bounded goals that persist
  across restarts and can be listed, edited, paused and run from ai-tui,
  ai-gui and =ai loop= / =ai goal=. See
  [[file:docs/loops-and-goals.org][docs/loops-and-goals.org]].
- Plan mode on =Shift-Tab= in ai-tui.
- Build provenance: the commit, a dirty flag, the build date, the source
  directory and the install paths are embedded at build time.
  =ai_build_info_*()= reads them, including from bindings, and =--version=
  in =ai=, =ai-tui= and =ai-gui= prints them.
- Self-update from the checkout that built the binary: =ai --check-update=
  (=--json=), =ai --update=, and =/update [status]= in ai-tui and ai-gui,
  with an opt-in background check (=updates.check=, also =ai --setup= scope 4),
  an update badge in ai-tui, and in ai-gui a banner,
  an Update button (pkexec for a privileged install), "Check for Updates" in
  the menu and "Restart now" after an install.
  See [[file:docs/updating.org][docs/updating.org]].
- =updates:= configuration section: =check=, =interval=, =upstream=,
  =source-dir=, =run-tests=. Matching =AiConfig= properties.
- This changelog.

* Versioning

Every pull request that changes behaviour bumps the version in =config.mk=
and adds its entry under a heading for that version at the top of this
file, in the same PR. =make test= fails when the newest heading here does
not match =config.mk= (=make test-version=). The rules, and what counts as
a feature or a fix, are in [[file:docs/contributing.org::*Versioning][docs/contributing.org]].

Tags are the maintainer's, after merge; nothing in the tree pushes one:

#+begin_example
git tag -a v0.4.0 -m "ai-glib 0.4.0"
git push origin v0.4.0
#+end_example

After a tag, =git describe= in every build says =v0.4.0-N-g<commit>=, which
is what =--version= shows.
