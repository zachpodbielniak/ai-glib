* Tool Executor
=AiToolExecutor= provides built-in tool implementations and manages the multi-turn tool-use loop with any =AiProvider= that supports tools (HTTP providers: Claude, OpenAI, Gemini, Grok, Ollama).

** Built-in Tools
| Tool         | Description                                                    |
|--------------+----------------------------------------------------------------|
| =bash=       | Run a shell command; stdout + stderr returned                  |
| =read=       | Read a file; supports =offset= and =limit= parameters          |
| =write=      | Write a file (create or overwrite)                             |
| =edit=       | Replace the first occurrence of =old_string= with =new_string= |
| =glob=       | Find files matching a glob pattern (recursive)                 |
| =grep=       | Search file contents with a regex; returns =file:line: match=  |
| =ls=         | List a directory with type and size                            |
| =web_fetch=  | Fetch a URL; HTML converted to text, optional model extraction |
| =web_search= | Search the web; ranked results + optional page fetch (below)   |

** Working directory
All seven filesystem tools resolve relative paths against the executor's working
directory, and =bash= runs its command there:

#+begin_src C
ai_tool_executor_set_working_directory (executor, "/home/me/src/project");
#+end_src

An agent is given work to do /somewhere/ -- a project, a checkout, a notes tree
-- and refers to =src/main.c=, not to an absolute path. With no working
directory set (the default) those resolve against the host process's own
current directory, which for something long-lived like an editor is wherever the
user last visited a file: almost never what the model meant.

An absolute path from the model is always used as given. Pass =NULL= to restore
the default.

=bash= spawns through =GSubprocess= rather than =popen()= so the directory can
be set at all, which also makes the command cancellable through the
=GCancellable= passed to the run and keeps its output valid UTF-8 -- a build log
carries progress bars and stray locale-encoded bytes, and that output is about
to become a JSON string.

** Quick Start
#+begin_src C
#include <ai-glib.h>

/* Create executor with all built-in tools */
g_autoptr(AiToolExecutor) exec = ai_tool_executor_new();

/* Create a provider (any HTTP provider) */
g_autoptr(AiClaudeClient) client = ai_claude_client_new();

/* Build the message list */
g_autoptr(AiMessage) msg = ai_message_new_user(
    "List all .c files in /tmp and show the first 10 lines of each.");
GList *messages = g_list_append(NULL, msg);

/* Run the full tool-use loop */
g_autoptr(GError) err = NULL;
g_autofree gchar *reply = ai_tool_executor_run(
    exec,
    AI_PROVIDER(client),
    messages,
    NULL,   /* system prompt */
    4096,   /* max tokens */
    NULL,   /* cancellable */
    &err
);
g_list_free(messages);

if (err != NULL) {
    g_printerr("Error: %s\n", err->message);
} else {
    g_print("%s\n", reply);
}
#+end_src

** web_search
=web_search= returns ranked results (title, URL, source domain, snippet) and
can optionally fetch the top results' pages. It is registered the moment you
set a search provider:

#+begin_src C
/* Zero-config: Brave/Bing from the environment, else keyless DuckDuckGo. */
g_autoptr(AiSearchProvider) sp = ai_search_provider_new_default(NULL);
ai_tool_executor_set_search_provider(exec, sp);

/* ...or choose a backend explicitly: */
g_autoptr(AiBraveSearch) brave = ai_brave_search_new("YOUR_BRAVE_API_KEY");
ai_tool_executor_set_search_provider(exec, AI_SEARCH_PROVIDER(brave));
#+end_src

The tool advertises these parameters to the model:

| Parameter       | Type    | Notes                                          |
|-----------------+---------+------------------------------------------------|
| =query=         | string  | required                                       |
| =count=         | number  | maximum results (default 10)                   |
| =freshness=     | enum    | any / day / week / month / year                |
| =safesearch=    | enum    | off / moderate / strict                        |
| =country=       | string  | two-letter region code, e.g. "US"              |
| =language=      | string  | two-letter language code, e.g. "en"            |
| =site=          | string  | restrict to one domain, e.g. "example.com"     |
| =fetch_content= | boolean | fetch + attach the top results' page text      |

Results are cached for 5 minutes (keyed by provider + query + options). When
=fetch_content= is set, each fetched page also rides the 15-minute =web_fetch=
cache, so a later =web_fetch= of the same URL is free.

*** Providers
| Provider             | Key env var     | Notes                             |
|----------------------+-----------------+-----------------------------------|
| =AiBraveSearch=      | =BRAVE_API_KEY= | [[https://brave.com/search/api/]] |
| =AiBingSearch=       | =BING_API_KEY=  | Azure Bing Search v7              |
| =AiDuckDuckGoSearch= | (none)          | keyless, best-effort (no SLA)     |

See [[file:web-search.org][Web Search]] for the full guide and
[[file:api-reference/ai-search-provider.org][AiSearchProvider]] for the API
reference.

*** Adding a new search provider
Implement the =AiSearchProvider= interface --- a single vfunc that returns a
=GList= of =AiSearchResult= (transfer full):

#+begin_src C
static GList *
my_do_search(AiSearchProvider *provider, const gchar *query,
             AiSearchOptions *options, GCancellable *cancellable,
             GError **error)
{
    GList *results = NULL;
    /* ... query your backend; for each hit: ... */
    AiSearchResult *r = ai_search_result_new(title, url, snippet);
    ai_search_result_set_rank(r, rank);
    results = g_list_append(results, r);
    return results;   /* caller frees: g_list_free_full(.., g_object_unref) */
}

static void
my_iface_init(AiSearchProviderInterface *iface)
{
    iface->search = my_do_search;
}

G_DEFINE_TYPE_WITH_CODE(MySearch, my_search, G_TYPE_OBJECT,
    G_IMPLEMENT_INTERFACE(AI_TYPE_SEARCH_PROVIDER, my_iface_init))
#+end_src

Return =NULL= with =*error= set on failure; return an empty list (=NULL=,
no error) when there are simply no results.

** Custom Tools
User-supplied callbacks register alongside the built-ins. The same multi-turn loop dispatches both --- the model sees the union of built-in tools and your callbacks via =ai_tool_executor_get_tools()=.

#+begin_src C
static gchar *
my_lookup (AiToolUse    *tool_use,
           GCancellable *cancellable,
           GError      **error,
           gpointer      user_data)
{
    const gchar *q = ai_tool_use_get_input_string (tool_use, "query");
    /* ... */
    return g_strdup_printf ("looked up: %s", q ? q : "");
}

g_autoptr(AiToolExecutor) exec = ai_tool_executor_new ();
g_autoptr(AiTool) tool = ai_tool_new ("my_lookup", "Look something up");
ai_tool_add_parameter (tool, "query", "string", "what to look up", TRUE);

ai_tool_executor_register_callback (exec, tool, my_lookup,
                                    /* user_data */ NULL,
                                    /* user_data_free */ NULL);

/* The model now sees both my_lookup and the built-ins. */
g_autofree gchar *answer = ai_tool_executor_run (
    exec, AI_PROVIDER (provider), messages, NULL, 4096, NULL, &error);
#+end_src

*** Callback signature
#+begin_src C
typedef gchar * (*AiToolCallback) (
    AiToolUse    *tool_use,
    GCancellable *cancellable,
    GError      **error,
    gpointer      user_data);
#+end_src

Return a newly-allocated string (freed by the executor). Returning =NULL= with =*error= set causes the loop to emit an error result back to the model so it can recover.

*** Overriding a built-in
Registering a callback whose name matches a built-in (e.g. ="bash"=) replaces the built-in for this executor. To revert, call =ai_tool_executor_unregister(exec, "bash")=.

A full worked example lives in [[file:examples/tool-use-executor.org][=examples/tool-use-executor.c=]].

** Continuing a conversation

=ai_tool_executor_run()= works on a private copy of your message list.  It
appends each assistant turn and tool result to that copy and frees the lot on
the way out, so you get the final text and no record of how the model got
there.  Send a follow-up on top of that and the model cannot see its own
previous turn --- which is not a continuation at all.

=ai_tool_executor_run_full()= hands the generated messages back:

#+begin_src C
GList *produced = NULL;
g_autofree gchar *reply = ai_tool_executor_run_full (
    exec, provider, messages, system_prompt, 4096, NULL,
    &produced, &error);

/* `produced' holds only what this run generated -- the assistant turns
   and tool results -- and never your originals.  Append it to whatever
   owns the conversation, and the next run continues rather than
   restarting. */
for (GList *l = produced; l != NULL; l = l->next)
    my_session_append (session, l->data);

g_list_free_full (produced, g_object_unref);
#+end_src

The out parameter is =(transfer full)=: you own the list and the messages in
it.  Passing =NULL= for it is exactly =ai_tool_executor_run()=, which is now
literally a wrapper.  On error the list is cleared and set to =NULL=, so a
caller who got =NULL= back has nothing to remember to free.

The final assistant message is included even though nothing in the run itself
reads it again --- it is the one message a continuation needs most, and
omitting it would leave the model's actual answer as the single thing missing
from the replayed history.

** Low-level API
For cases where you manage the provider loop yourself:

#+begin_src C
/* Get the tool list to pass to ai_provider_chat_async() */
GList *tools = ai_tool_executor_get_tools(exec);   /* transfer none */

ai_provider_chat_async(provider, messages, system, max_tokens, tools,
                       NULL, on_response, user_data);

/* In on_response: execute tool calls */
GList *uses = ai_response_get_tool_uses(response);
for (GList *i = uses; i; i = i->next) {
    g_autofree gchar *result = ai_tool_executor_execute(
        exec, i->data, NULL, NULL);
    /* build tool result message and continue conversation */
}
g_list_free(uses);
#+end_src

** The =web_fetch= tool
=web_fetch= retrieves a URL and returns content tuned for a model rather
than the raw bytes:

- *HTML to text*: =text/html= responses are parsed (libxml2) and rendered
  to readable markdown-ish text --- =script=/=style=/=head= are dropped,
  headings become =#= prefixes, =<a href>= becomes =[text](href)=, and
  =<img src>= becomes =![alt](src)= with the src resolved to an absolute
  URL (honoring a =<base href>=) so the model gets directly-fetchable
  image links.  =application/json= and other =text/*= responses pass
  through unchanged; binary types return a short placeholder instead of
  garbage.
- *Hardening*: =http://= URLs are upgraded to =https://= (with fall-back),
  a real =User-Agent= is sent, the request times out after 30 s, and a
  redirect to a different host is announced with a =[redirected to ...]=
  notice line.
- *Caching*: converted bodies are cached in-process for *15 minutes*,
  keyed by URL; repeated fetches within a session avoid the network. The
  cache is self-cleaning (expired entries are dropped on access).
- *Optional extraction*: pass a =prompt= parameter and a model reads the
  fetched content and returns only the requested information instead of
  the whole page. Extraction uses the provider driving the current
  =ai_tool_executor_run()= call; if no run is active (e.g. a bare
  =ai_tool_executor_execute()=) the =prompt= is ignored and the converted
  content is returned. Extraction failures fall back to the content.

Parameters: =url= (required), =prompt= (optional).

** Limits
- =ai_tool_executor_run()= caps at *20 turns* to prevent infinite loops.
- =web_fetch= returns at most *100 KB* of converted text (truncated on a
  valid UTF-8 boundary, with a =[truncated at 100 KB]= marker).
- Tools run on the calling thread; =bash= commands block until completion.

* Watching the loop
=AiToolExecutor= implements [[file:api-reference/ai-event-source.org][AiEventSource]], so a
frontend can see the loop happen rather than only its result. It brackets
each call with =AI_EVENT_TOOL_STARTED= and =AI_EVENT_TOOL_FINISHED=, and
republishes the provider's own events on the same stream --- so one
subscription shows the whole turn, the model's prose and the tool activity
together, in the order they happened.

#+begin_src C
g_signal_connect (executor, "event", G_CALLBACK (on_event), self);
#+end_src

Started is emitted *before* the call runs. A tool that takes thirty seconds
should show as running for thirty seconds, not appear retroactively when it
finishes.

The =source= label on each event distinguishes the two --- ="AiToolExecutor"=
for a locally run tool, the provider's type name for everything it
forwarded.

* Streaming
| Property  | Type    | Default |
|-----------+---------+---------|
| =stream=  | boolean | =FALSE= |

The loop has always used =ai_provider_chat_async()=, so a caller got live
tokens *or* tool execution and never both. With this set and an
=AiStreamable= provider, each turn goes through
=ai_streamable_chat_stream_async()= instead.

It defaults to =FALSE= so every existing caller takes the path it always
did. [[file:api-reference/ai-conversation.org][AiConversation]] sets it from
its own =stream= property.

* Tool approval
| Property            | Type             | Default                   |
|---------------------+------------------+---------------------------|
| =approval-policy=   | =AiToolApproval= | =AI_TOOL_APPROVAL_ALLOW=  |

| Signal                 | Arguments             | Returns          |
|------------------------+-----------------------+------------------|
| =approval-requested=   | =AiToolUse *tool_use= | =AiToolApproval= |

#+begin_src C
typedef enum
{
    AI_TOOL_APPROVAL_DEFAULT = 0,   /* no opinion; defer to approval-policy */
    AI_TOOL_APPROVAL_ALLOW,
    AI_TOOL_APPROVAL_DENY,          /* refuse this call, continue the run   */
    AI_TOOL_APPROVAL_ALLOW_ALWAYS,  /* and stop asking about this tool      */
    AI_TOOL_APPROVAL_DENY_ALL       /* refuse and abort the run             */
} AiToolApproval;
#+end_src

** Why DEFAULT is zero
A signal with no handlers accumulates to zero. Zero is =DEFAULT=, which
resolves through =approval-policy= to =ALLOW= --- so an executor nobody is
watching behaves exactly as it did before approval existed. That is a
property of the design rather than a compatibility branch, and
=tests/test-tool-executor-approval.c= asserts it first.

Set =approval-policy= to =AI_TOOL_APPROVAL_DENY= for an unattended agent:
nobody is there to say yes, so an unanswered call should be a refusal rather
than a silent grant.

** The accumulator
Not =g_signal_accumulator_first_wins=, which halts after the first handler
*whatever it returns* --- so a handler answering =DEFAULT= would silently
veto every handler behind it, which is the opposite of what "no opinion"
should mean. The accumulator here keeps asking while the answer is =DEFAULT=
and stops at the first real decision.

** DENY continues the run
A refusal is reported to the model as the tool's result. It will usually
acknowledge it and try something else, which is more useful than a turn that
simply stops. Only =DENY_ALL= aborts.

=ALLOW_ALWAYS= is remembered for one run, not for the executor: an answer
given about one task is not consent for the next.

** The nested-loop rule
A handler that asks a human must spin a nested =GMainLoop= on
=g_main_context_get_thread_default()= --- *not* the global default, which a
caller driving the run from a private context would never dispatch. The
call is synchronous at that point by design: the tool has not run, and
nothing else about the turn may proceed until the answer arrives.

#+begin_src C
static gint
on_approval (AiToolExecutor *exec, AiToolUse *tool_use, gpointer data)
{
    /* ... draw a prompt, read a key, iterating
       g_main_context_get_thread_default() while waiting ... */
    return AI_TOOL_APPROVAL_ALLOW;
}
#+end_src

=bin/ai-tui.c= is a worked example.

** This never fires for the CLI wrappers
claude-code, opencode, grok-build, antigravity and cursor run their own tools inside their own
processes; ai-glib never sees those calls, so it cannot offer them for
approval. Their equivalent is =--skip-permissions= and the per-provider
=permission-mode= and =allowed-tools= properties. That is also why
[[file:api-reference/ai-conversation.org][AiConversation]] refuses
=local-tools= for them.

* The harness-aware tools
Setting a resource registry adds two more:

#+begin_src C
ai_tool_executor_set_resource_registry (executor, registry);
#+end_src

- =task= runs an agent file from disk as a subagent, confined to the
  tools that file declares.
- =skill= lets the model load a written procedure for itself.

While no registry is set neither tool exists, so an executor built by
=ai_tool_executor_new()= advertises exactly what it always has --- adding
subagent support to the library changed nothing for callers who do not
want it.

*The tool list is the grant.* A built-in dispatches only while the
executor advertises it, which is what makes =task='s allowlist structural
rather than a policy: an agent whose =tools:= omits =bash= has no =bash=
to call. Without that, the dispatch table being global would have made
the allowlist decoration.

See [[file:tools.org][The built-in tools]] for every tool's parameters
and failure modes, and [[file:harness.org][the harness layer]] for where
the files come from.

* Errors reach the model
When a tool returns %NULL, its =GError= message becomes the tool result,
prefixed with "Error: ". That is what makes an error worth wording: "no
agent named 'reviewr'. Available: reviewer, auditor" gives the model
something to do next, where "tool execution failed" gives it nothing.
