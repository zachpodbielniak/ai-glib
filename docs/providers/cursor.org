* Cursor Provider
The Cursor provider (=AiCursorClient=) wraps Cursor's =cursor-agent= CLI
(the =agent= CLI) in =--print= mode. It is the agentic counterpart to
talking to a model over HTTP: this one drives Cursor's coding agent, with
its tools, sessions, sandbox, worktrees and MCP servers.

The default binary is =cursor-agent= rather than =agent=: grok also ships
an =agent= on =$PATH=, and the Cursor install provides both names.

** Overview
| Property      | Value                     |
|---------------+---------------------------|
| Type          | =AI_PROVIDER_CURSOR=      |
| Name          | "Cursor"                  |
| Default Model | =auto=                    |
| Interface     | CLI (subprocess)          |
| Binary        | =cursor-agent=            |
| Aliases       | =cursor=, =cursor-agent=  |

** Requirements
- The Cursor Agent CLI must be installed and authenticated
  (=cursor-agent login=)
- The CLI must be available in =$PATH= as =cursor-agent=, or named via
  =CURSOR_AGENT_PATH= / =CURSOR_PATH=

** Environment Variables
| Variable             | Description |
|----------------------+-------------|
| =CURSOR_AGENT_PATH=  | Override the path to the =cursor-agent= executable (wins) |
| =CURSOR_PATH=        | Fallback override if =CURSOR_AGENT_PATH= is unset |
| =CURSOR_API_KEY=     | Optional API key; also settable as the =api-key= property, which is delivered as this env var rather than as =--api-key= (so it never appears in =ps=) |
| =CURSOR_API_ENDPOINT= | The CLI's own endpoint override; the =endpoint= property emits =--endpoint= instead |

The CLI's stored credentials are read by =cursor-agent= itself.

** Available Models
Run =cursor-agent models= for the authoritative list; the CLI rejects
unknown ids rather than falling back. Parameterized models also accept
quoted bracket overrides, e.g.
=--model 'claude-opus-4-8[context=1m,effort=high,fast=false]'= --- see
=model-params=.

** How the prompt is delivered
The prompt is *not* passed as a positional argv word. =--print= is a
boolean (unlike =agy --print=, which consumes the next word), so flags
after it are safe. The conversation is still piped on stdin so a long
turn never hits =MAX_ARG_STRLEN= and never appears in =ps=.

A non-streaming turn is:

#+begin_example
cursor-agent --print --output-format json --model auto ...
#+end_example

A streaming turn adds =--output-format stream-json= and
=--stream-partial-output=.

The conversation is flattened into a single prompt: user messages
verbatim, assistant messages prefixed =Previous assistant response:=,
joined with blank lines, and a trailing instruction to always produce a
text summary rather than ending on tool calls. On a fresh session the
system prompt is wrapped in =<system>...</system>=. Resume / continue
turns omit it.

than aborting a =G_DEBUG=fatal-warnings= run.

** Signals
The streaming signals are declared on =AiCliClient= and emitted by this client:

| Signal         | Arguments      | When |
|----------------+----------------+------|
| =stream-start= | —              | Before the first text delta |
| =delta=        | =const gchar*= | Each assistant text delta |
| =stream-end=   | =AiResponse*=  | At EOF, with the assembled response |

With =--stream-partial-output=, only assistant events that carry
=timestamp_ms= and no =model_call_id= are new text. The others are
duplicate flushes and are ignored.

Tool start/finish are reported on the =::event= stream as
=AI_EVENT_TOOL_STARTED= / =AI_EVENT_TOOL_FINISHED=, keyed by
=call_id=. cursor-agent runs its own tools inside the CLI; they are not
executed by =AiToolExecutor=.

** JSON shape
Non-streaming =--output-format json= is Cursor's own envelope:

#+begin_src json
{"type":"result","subtype":"success","is_error":false,"result":"...","session_id":"..."}
#+end_src

=is_error= is an error even when the process exits 0. Parse stdout first.

Streaming is NDJSON: =system= / =user= / =assistant= / =tool_call=
(started, completed) / =result=.

** Usage
*** Basic Usage
#+begin_src C
#include <ai-glib.h>

int main(void)
{
    g_autoptr(AiCursorClient) client = ai_cursor_client_new();
    g_autoptr(AiMessage) msg = ai_message_new_user("Hello!");
    GList *messages = g_list_append(NULL, msg);

    ai_provider_chat_async(
        AI_PROVIDER(client),
        messages,
        NULL,
        4096,
        NULL,
        NULL,
        on_chat_complete,
        user_data
    );

    g_list_free(messages);
    return 0;
}
#+end_src

*** Skip permissions
#+begin_src C
ai_cursor_client_set_skip_permissions(client, TRUE);
#+end_src

From the CLI this is =ai -p cursor --skip-permissions=.

*** Sessions
A session id captured from =session_id= is sent as =--resume <id>= on the
next turn. =--continue= is only emitted when there is no id:
=ai -p cursor -c=. An explicit session id always wins over it.

*** Model overrides
#+begin_src C
ai_cli_client_set_model(AI_CLI_CLIENT(client), AI_CURSOR_MODEL_COMPOSER_2_5);
g_object_set(client, "model-params", "context=1m,effort=high", NULL);
#+end_src

** From the =ai= CLI
#+begin_example
$ ai -p cursor --dry-run "hi"
$ ai -p cursor -m composer-2.5 --skip-permissions "summarise this repo"
$ ai -p cursor -c "continue from last time"
$ ai -p cursor --set mode=plan --set sandbox=disabled --set trust --dry-run "hi"
$ ai -p cursor --set model-params=context=1m,effort=high --dry-run "hi"
#+end_example
