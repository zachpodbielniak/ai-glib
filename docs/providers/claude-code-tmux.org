* Claude Code (tmux) Provider
The Claude Code (tmux) provider (=AiClaudeTmuxClient=) drives the =claude= CLI in its *native interactive TUI* by spawning it inside an ephemeral [[https://github.com/tmux/tmux][tmux]] session. Unlike [[file:claude-code.org][=AiClaudeCodeClient=]] --- which uses =claude --print= (the Agent SDK / non-interactive path) --- this client speaks to a fully interactive =claude= process and so consumes the user's *normal subscription budget* rather than the Agent SDK credit pool.

This was introduced because Anthropic's Agent SDK billing path is changing 2026-06-15, and subscription-budget users wanted a way to continue routing automated workloads through their existing plan.

** Overview
| Property      | Value                             |
|---------------+-----------------------------------|
| Type          | =AI_PROVIDER_CLAUDE_TMUX=         |
| Name          | "Claude Code (tmux)"              |
| Default Model | =sonnet=                          |
| Interface     | CLI (subprocess wrapped in tmux)  |
| Billing path  | Subscription (TUI), not Agent SDK |

** Requirements
- The =claude= CLI must be installed, logged in, and on =$PATH= (or pointed at via =CLAUDE_CODE_PATH=).
- The =tmux= binary must be installed and on =$PATH= (or pointed at via =ai_claude_tmux_client_set_tmux_path()=).
- A writable =~/.claude/projects/= directory (or override via =set_claude_project_dir()=).

** Dedicated tmux socket (=-L=)
Every tmux command this client runs is pinned to its own server socket via
=tmux -L <socket>=. The default is =ai-glib=; embedders should set their own:

#+begin_src C
ai_claude_tmux_client_set_socket_name(client, "libreclaw");
#+end_src

This is a safety property, not a preference. A bare =tmux= talks to the
=default= socket, so a client that omitted =-L= would put its sessions on the
*same server process* as any tmux the user started by hand --- and a tmux
server is all-or-nothing: whatever kills it kills every session on it. A
session-teardown on our side, or anything that reaps the server's cgroup,
would take the user's own work down with it. That is not theoretical; it cost
a live working session before this was fixed. On a private socket the two are
mutually invisible: we cannot see or kill the user's sessions, and they cannot
see ours.

Inspect or attach to a session with the same =-L=:

#+begin_example
tmux -L libreclaw list-sessions
tmux -L libreclaw attach -t claudetmux-<uuid>
#+end_example

Setting the socket name to =NULL= or ="= restores the default rather than
falling back to =default=, so the isolation cannot be lost by accident.

On first use the client also runs =start-server= and =set-option -s exit-empty
off= on that socket. Without =exit-empty off= the server exits as soon as its
last session ends --- i.e. after every turn --- and each turn's replacement
server is born into whatever cgroup that turn happened to run in. Both
commands are best-effort: failures are logged at =g_debug= and the turn
proceeds (=new-session= starts a server by itself).

** Ollama transport ("ollama/" models)
Like the [[file:claude-code.org][non-tmux client]], a model name beginning with =ollama/= routes
the turn through Ollama as the transport. The =ollama launch claude= wrapper
is inlined inside the tmux command, *after* the tmux =--=:

#+begin_example
tmux -L <socket> new-session -d -s <name> -c <cwd> -- \
     ollama launch claude --model <suffix> -- \
     --session-id <uuid> --settings <json> [args]
#+end_example

So for =ollama/glm-5.2:cloud= the program tmux launches is =ollama= (override
with =OLLAMA_PATH=), which in turn launches the =claude= TUI. claude's own
=--model= flag is omitted (the model is carried by =ollama launch --model=);
=claude= must still be installed and on =$PATH=. Models without the =ollama/=
prefix are unchanged. Verify the exact command with:
=ai -p claude-tmux -m ollama/glm-5.2:cloud --dry-run "hi"=.

** How It Works
Each call to =ai_provider_chat_sync()= (or its async equivalent) goes through this sequence:

1. *Generate a session UUID* (or reuse the configured one). If a transcript already exists for that UUID the session is /resumed/ (=claude --resume=) rather than created fresh (=claude --session-id=).
2. *Write the prompt* to a temp file atomically.
3. *Spawn* =tmux -L <socket> new-session -d -s <name> -- claude [--session-id|--resume] <uuid> --settings '<json>' [args]=. The settings install a =Stop= hook that touches a per-session sentinel file when claude finishes a turn, and a =SessionStart= hook that touches a /ready/ sentinel once claude's TUI is initialized.
4. *Wait* for the =SessionStart= ready sentinel --- proof the TUI is live and able to receive input.
5. *Dismiss the resume-mode picker* (resumed sessions only) --- see /Resume-mode picker/ below.
6. *Capture the byte offset* of the JSONL file as =jsonl_size_before= --- the high-water mark for "everything written before this turn."
7. *Deliver the prompt*: load it into a tmux paste-buffer and paste it into the TUI as a bracketed-paste event (multi-line safe), then send a *verified* Enter --- see /Verified submit/ below.
8. *Wait* for the =Stop=-hook sentinel, then poll the JSONL for a *terminal assistant entry* past =jsonl_size_before= --- see /Stop-hook / JSONL flush race/ below.
9. *Parse* the JSONL: extract the last assistant entry's text blocks and usage, return as =AiResponse=.
10. *Tear down*: kill the tmux session, unlink the prompt + sentinel files. (Optionally preserved --- see =debug-preserve-tmux= below.)

*** Stop-hook / JSONL flush race
A subtle gotcha worth documenting: the Stop hook fires when =claude= has generated its assistant response *in memory*, but the on-disk JSONL flush of that response lags the flush of the user-message + attachment lines by up to ~2 seconds. A naive "wait for the file to grow past =jsonl_size_before=" check fires too early and reads the *previous* turn's last assistant entry, returning a stale response.

The poll loop therefore parses the slice of JSONL past =jsonl_size_before= and waits for an entry where:

- =type == "assistant"=, *and*
- =message.stop_reason= is set and is *not* ="tool_use"=.

=tool_use= stop reasons are intermediate; the Stop hook only fires on terminal reasons (=end_turn=, =stop_sequence=, =max_tokens=), so we're guaranteed to converge.

*** Verified submit
=tmux send-keys= is not perfectly reliable at landing the submit Enter against the claude TUI --- a keypress can be swallowed while the input box is mid-render. A swallowed Enter means claude never receives the prompt, so the client would otherwise burn the whole turn timeout waiting on a =Stop= hook that never fires.

So the Enter is treated as unconfirmed until proven otherwise. After pressing it, the client polls the JSONL slice past =jsonl_size_before= for proof that claude *accepted* the submission, which has two shapes:

- a real =type:"user"= entry (not a compaction summary) --- claude was idle and started the turn immediately; or
- a =type:"queue-operation"= entry with =operation:"enqueue"= --- claude was *busy* (running a turn, or auto-compacting a large resumed session) and /queued/ the prompt. It is not lost: it runs as soon as claude is free, and the (deliberately generous) turn timeout covers the wait.

If neither shape appears within =prompt-resend-interval-ms=, the Enter is re-sent, up to =max-prompt-send-attempts= times before the turn fails with =AI_ERROR_CLI_EXECUTION=. Recognising the /queued/ shape matters: an earlier cut looked only for =type:"user"=, mistook a queued prompt for a swallowed keystroke, and tore the tmux session down mid-compaction with the message still in claude's queue. =type:"user"= entries flagged =isCompactSummary= (a finished compaction's own summary) are excluded --- they would be a false positive.

The classification is a pure function, =ai_claude_tmux_client_jsonl_has_accepted_prompt()=, exported so it can be unit-tested without spawning =claude=.

*** Resume-mode picker
When a session is resumed, claude's TUI can stop on an interactive picker asking whether to resume "with a summary", "as-is", or "clear". Because this client always kills the tmux session at the end of a turn (claude never exits cleanly on its own), every resumed session looks "interrupted" to claude --- which is what triggers the picker. There is no CLI flag or settings-file key to suppress it.

Left alone, the picker swallows the pasted prompt as raw keystrokes. With =dismiss-resume-prompt= enabled (the default), the client types =2= --- the "resume as-is" option --- then waits =prompt-resend-interval-ms= for the TUI to settle before pasting. Plain Enter would take the picker's /default/, "resume with a summary", which kicks off a re-summarisation (a compaction) that on a large session can run for minutes; "resume as-is" skips that.

If no picker is actually shown, the =2= lands as a literal character prepended to the pasted prompt --- an accepted cosmetic trade-off. The dismissal only runs on resumed sessions; fresh sessions never show the picker.

*** Continuing a session
=continue-session= picks up the working directory's most recent
conversation, the way =claude --continue= does:

#+begin_src C
g_object_set(client, "continue-session", TRUE, NULL);
#+end_src

It does *not* pass =--continue=. Everything in this client is keyed by
session id --- the transcript it watches to detect the accepted prompt and
parse the reply is =<session-id>.jsonl= --- and =--continue= never reports
which session it picked, so the client would sit watching a path that never
appears. Instead it resolves the newest transcript in the directory's
project folder and resumes that *by id*. Same semantics, and the id stays
known.

Consequences worth knowing:

- An explicit =AiCliClient:session-id= wins, as with every other provider.
- With nothing to continue, a fresh session starts rather than the call
  failing.
- Because the result is a resume, the resume-mode picker described above
  applies, and =dismiss-resume-prompt= handles it.
- The lookup honours =claude-project-dir=, so a test can point it at a
  temporary tree.

From the CLI this is =ai -p claude-tmux -c=.

*** Entering from a provider switch
=ai_conversation_set_provider()= clears this target's session id and
=continue-session= before selecting it. The tmux client consequently creates
a new UUID and a fresh Claude session, then sends the completed portable
=AiMessage= history as the prompt for its first turn.

It does *not* inspect an older =<session-id>.jsonl= to recover context, choose
the newest transcript, or import provider-owned tool events. The JSONL logic
described above is used only to drive and read the new native session.
Completed tool calls/results already present in =AiConversation= survive as
labelled text in the CLI projection.

The conversation working directory and compatible MCP endpoint are applied
to the target. Local ai-glib tools are disabled because the interactive
Claude process owns tool execution. See
[[file:../provider-switching.org][Provider switching]] for the full contract.

** Usage
*** Basic Usage
#+begin_src C
#include <ai-glib.h>

int main(void)
{
    g_autoptr(AiClaudeTmuxClient) client = ai_claude_tmux_client_new();
    g_autoptr(AiMessage) msg = ai_message_new_user("Hello, Claude!");
    g_autoptr(AiResponse) response = NULL;
    g_autoptr(GError) error = NULL;
    GList *messages = g_list_append(NULL, msg);

    response = ai_provider_chat_sync(
        AI_PROVIDER(client),
        messages,
        "You are a helpful assistant.",
        4096,
        NULL,
        NULL,
        &error
    );

    if (error != NULL)
    {
        g_printerr("Error: %s\n", error->message);
        return 1;
    }

    g_print("%s\n", ai_response_get_text(response));
    g_list_free(messages);
    return 0;
}
#+end_src

*** Setting the Model
#+begin_src C
g_autoptr(AiClaudeTmuxClient) client = ai_claude_tmux_client_new();

#+end_src

*** Tuning Timeouts
The three relevant timeouts:

- *Startup timeout* --- how long to wait for claude's TUI to become ready (the =SessionStart= hook) after launch. Default: 15s.
- *Turn timeout* --- applied as an *inactivity* budget, not a hard wall-clock cap. The provider waits for the Stop-hook sentinel and resets this clock every time the JSONL transcript grows (claude writing an assistant step, tool call, or tool result). A long but actively-working turn therefore never times out; only a transcript that stays completely silent for the whole budget is treated as a wedged turn. Default: 600s (10 minutes) of *silence*. This is what lets multi-minute agentic turns (many tool calls) complete instead of being killed mid-flight — a still-running turn can always be aborted with =!stop= / =!kill= instead.
- *Command timeout* (=command-timeout-ms=, since 0.23.3) --- a deadline on every tmux /plumbing/ command the provider runs (=new-session=, =send-keys=, =load-buffer=, =paste-buffer=, =kill-session=, ...). These complete in milliseconds when tmux is healthy; the deadline only matters when the tmux server wedges, which would otherwise block the calling worker thread *forever* (this exact hang once froze a libreclaw session for hours). On expiry the tmux command is killed and the turn fails with =AI_ERROR_TIMEOUT=. Default: 30s. =0= disables (not recommended).

#+begin_src C
ai_claude_tmux_client_set_startup_timeout_ms(client, 30000);  /* 30s */
ai_claude_tmux_client_set_turn_timeout_ms(client, 180000);    /* 3m  */
ai_claude_tmux_client_set_command_timeout_ms(client, 10000);  /* 10s */
#+end_src

Cancelling the turn's =GCancellable= (libreclaw's =!stop= / =!kill=, or a caller-side watchdog) now also aborts any in-flight tmux plumbing command and kills its child process --- previously a wedged command was uncancellable.

*** Reliability tuning
Three properties control the prompt-delivery machinery (see /Verified submit/ and /Resume-mode picker/ above):

| Property                    | Default | Effect                                                                                                                    |
|-----------------------------+---------+---------------------------------------------------------------------------------------------------------------------------|
| =dismiss-resume-prompt=     | =TRUE=  | On a resumed session, type =2= ("resume as-is") to clear claude's resume-mode picker before pasting the prompt.           |
| =prompt-resend-interval-ms= | =2000=  | Per-attempt wait for the prompt to be accepted after an Enter --- also the settle wait after the resume-picker keystroke. |
| =max-prompt-send-attempts=  | =5=     | How many Enter keystrokes to try before failing the turn with =AI_ERROR_CLI_EXECUTION=.                                   |

#+begin_src C
ai_claude_tmux_client_set_dismiss_resume_prompt(client, TRUE);
ai_claude_tmux_client_set_prompt_resend_interval_ms(client, 2000);
ai_claude_tmux_client_set_max_prompt_send_attempts(client, 5);
#+end_src

The defaults suit normal use; you'd typically only raise =prompt-resend-interval-ms= / =max-prompt-send-attempts= on a very slow host.

*** Skip Permissions
For automated/headless workloads where you don't want claude to prompt for tool-permission approvals:

#+begin_src C
ai_claude_tmux_client_set_skip_permissions(client, TRUE);
#+end_src

This passes =--dangerously-skip-permissions= to =claude=. *Only use this in trusted environments* --- it bypasses claude's normal "ask before destructive actions" gating.

*** Debug Mode: preserve tmux + artifacts
When debugging a stuck or misbehaving turn, you can prevent the client from cleaning up after itself:

#+begin_src C
ai_claude_tmux_client_set_debug_preserve_tmux(client, TRUE);
#+end_src

This:

- Skips =tmux kill-session= after the turn --- you can =tmux -L <socket> attach -t claudetmux-<uuid>= to see the interactive session. Note the =-L=: without it you are talking to your *own* default tmux server, where the session does not exist.
- Skips unlinking the prompt file and sentinel files.
- Implies =keep-artifacts= behaviour.

Default is =FALSE=. Production callers should leave it off --- the per-turn artifacts pile up otherwise.

A lighter alternative if you only want to keep the temp files (without preserving the tmux session):

#+begin_src C
ai_claude_tmux_client_set_keep_artifacts(client, TRUE);
#+end_src

*** Overriding tmux / claude paths (testing)
For tests with a stand-in script:

#+begin_src C
ai_claude_tmux_client_set_tmux_path(client, "/tmp/fake-tmux.sh");
ai_claude_tmux_client_set_claude_project_dir(client, "/tmp/test-projects");
#+end_src

Production callers should leave both =NULL= (search =$PATH= / use =$HOME/.claude/projects=).

*** Getting Cost Information
The TUI doesn't always emit a cost field; missing values surface as =0.0=.

#+begin_src C
gdouble cost = ai_claude_tmux_client_get_total_cost(client);
g_print("Last turn cost: $%.4f\n", cost);
#+end_src

* Event coverage
On [[file:../events.org][the event stream]] this provider reports nothing yet --- it reads a finished JSONL transcript rather than a stream, so there is no line-by-line output to translate. It still works everywhere an #AiProvider works, and AiConversation folds its finished response into blocks.

** Slash commands and mentions
This provider resolves =@= file references and its own slash commands
itself, so ai-glib passes a line through byte-for-byte rather than
expanding first --- doing it twice would be worse than not at all, and
=/compact= and its friends would never arrive.

=AiConversation:passthrough-commands= defaults to =TRUE= here for that
reason. ai-glib's own built-ins (=/help=, =/clear=, =/quit= and the
listings) still run locally, because the wrapped tool has no opinion
about this program's transcript.

See [[file:../harness.org::*Passthrough][the harness layer]].

* Extra MCP servers through the endpoint interface

This client implements =AiToolEndpointConsumer=, so a host can hand it tools
without knowing which CLI it is. For an =AI_ENDPOINT_KIND_MCP_CONFIG= endpoint
delivery is the =mcp-config-path= property documented above --- the interface is
a second door onto the same state, not a parallel path that could disagree with
it.

Revoking (=ai_tool_endpoint_consumer_clear()=) clears the path, so a later run
cannot point at a config file that has since been deleted.

See [[file:../tools.org][Tools]] for the dialect/delivery split.
