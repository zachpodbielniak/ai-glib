* Claude Code Provider
The Claude Code provider (=AiClaudeCodeClient=) is a wrapper around the =claude= CLI tool from Anthropic. It allows you to use Claude through the command-line interface instead of direct HTTP API calls.

** Overview
| Property      | Value                     |
|---------------+---------------------------|
| Type          | =AI_PROVIDER_CLAUDE_CODE= |
| Name          | "Claude Code"             |
| Default Model | =sonnet=                  |
| Interface     | CLI (subprocess)          |

** Requirements
- The =claude= CLI must be installed and configured
- The CLI must be available in =$PATH= or specified via environment variable

** Installation
Install the Claude CLI following the official instructions from Anthropic. The CLI is part of the Claude Code product.

** Environment Variables
| Variable           | Description                                            |
|--------------------+--------------------------------------------------------|
| =CLAUDE_CODE_PATH= | Override the path to the =claude= executable           |
| =OLLAMA_PATH=      | Override the path to the =ollama= launcher (Ollama transport, below) |

** Available Models
Both forms below are valid =--model= arguments to the =claude= CLI.

The short aliases *float*: the CLI resolves each to the newest model of that
tier, so they follow new releases without a code change.

| Define                         | Model Alias |
|--------------------------------+-------------|
| =AI_CLAUDE_CODE_MODEL_FABLE=   | ="fable"=   |
| =AI_CLAUDE_CODE_MODEL_OPUS=    | ="opus"=    |
| =AI_CLAUDE_CODE_MODEL_SONNET=  | ="sonnet"=  |
| =AI_CLAUDE_CODE_MODEL_HAIKU=   | ="haiku"=   |
| =AI_CLAUDE_CODE_DEFAULT_MODEL= | ="sonnet"=  |

Use a full Claude 5 ID instead to *pin* a generation. 1M context is the
default and the maximum for this generation, so no =[1m]= / =-1m= suffix
exists or is accepted.

| Define                          | Model ID          |
|---------------------------------+-------------------|
| =AI_CLAUDE_CODE_MODEL_FABLE_5=  | ="claude-fable-5"=  |
| =AI_CLAUDE_CODE_MODEL_OPUS_5=   | ="claude-opus-5"=   |
| =AI_CLAUDE_CODE_MODEL_SONNET_5= | ="claude-sonnet-5"= |

=ai_provider_list_models()= reports all seven: the four aliases followed by
the three pinned Claude 5 IDs. The list is advisory --- this provider passes
any =--model= string through to the CLI verbatim without validating it.

** Ollama transport ("ollama/" models)
Ollama can drive the Claude Code CLI as its transport. When the model name
begins with the prefix =ollama/=, this provider does NOT spawn =claude=
directly; instead it spawns:

#+begin_example
ollama launch claude --model <model-after-prefix> -- <the claude args>
#+end_example

For example, model =ollama/glm-5.2:cloud= produces:

#+begin_example
ollama launch claude --model glm-5.2:cloud -- --print --output-format json ...
#+end_example

Notes:
- The =--model= flag is consumed by =ollama launch=; claude's own =--model=
  flag is omitted (the Ollama model id is not a claude alias).
- The =claude= binary must still be installed and on =$PATH= --- =ollama
  launch claude= execs it.
- The launcher binary is =ollama= (override with =OLLAMA_PATH=).
- The prefix match is exact and case-sensitive: =ollama= (no slash) and
  =ollama/= (empty suffix) are NOT the transport and select a normal model.
- Models WITHOUT the =ollama/= prefix are unchanged --- =claude= is spawned
  directly as before.

This is handy for routing local or Ollama-cloud models through the same
Claude Code agent surface. Verify the exact command with the =ai= CLI:
=ai -p claude-code -m ollama/glm-5.2:cloud --dry-run "hi"=.

** Usage
*** Basic Usage
#+begin_src C
#include <ai-glib.h>

int main(void)
{
    g_autoptr(AiClaudeCodeClient) client = ai_claude_code_client_new();
    g_autoptr(AiMessage) msg = ai_message_new_user("Hello, Claude!");
    GList *messages = g_list_append(NULL, msg);

    /* Async chat request */
    ai_provider_chat_async(
        AI_PROVIDER(client),
        messages,
        "You are a helpful assistant.",  /* system prompt */
        4096,                             /* max tokens */
        NULL,                             /* tools */
        NULL,                             /* cancellable */
        on_chat_complete,
        user_data
    );

    g_list_free(messages);
    return 0;
}
#+end_src

*** Setting the Model
#+begin_src C
g_autoptr(AiClaudeCodeClient) client = ai_claude_code_client_new();

/* Use Opus model */
ai_cli_client_set_model(AI_CLI_CLIENT(client), AI_CLAUDE_CODE_MODEL_OPUS);

/* Or use Haiku for faster responses */
ai_cli_client_set_model(AI_CLI_CLIENT(client), AI_CLAUDE_CODE_MODEL_HAIKU);
#+end_src

*** Session Management
Claude Code supports session persistence for multi-turn conversations:

#+begin_src C
g_autoptr(AiClaudeCodeClient) client = ai_claude_code_client_new();

/* Enable session persistence */
ai_cli_client_set_session_persistence(AI_CLI_CLIENT(client), TRUE);

/* After first request, a session ID will be set automatically */
/* You can retrieve it for debugging or logging */
const gchar *session_id = ai_cli_client_get_session_id(AI_CLI_CLIENT(client));

/* Or set a specific session ID to resume a conversation */
ai_cli_client_set_session_id(AI_CLI_CLIENT(client), "previous-session-id");
#+end_src

*** Process Timeout
/Since 0.23.3./ Synchronous chat calls (=ai_cli_client_chat_sync()=) are bounded by a wall-clock deadline, =process-timeout-ms= (default 30 minutes, =0= disables). On expiry the =claude= child process is killed and the call fails with =AI_ERROR_TIMEOUT= --- previously a CLI wedged on a dead network connection could block the calling thread forever. Cancelling the call's =GCancellable= now also kills the child instead of leaking it.

#+begin_src C
g_autoptr(AiClaudeCodeClient) client = ai_claude_code_client_new();

/* Fail any single claude run that takes longer than 10 minutes */
ai_cli_client_set_process_timeout_ms(AI_CLI_CLIENT(client), 600000);
#+end_src

*** Getting Cost Information
Claude Code provides cost information in its responses:

#+begin_src C
static void
on_chat_complete(GObject *source, GAsyncResult *result, gpointer user_data)
{
    g_autoptr(AiResponse) response = ai_provider_chat_finish(
        AI_PROVIDER(source), result, NULL);

    /* Get the cost from the last request */
    gdouble cost = ai_claude_code_client_get_total_cost(
        AI_CLAUDE_CODE_CLIENT(source));
    g_print("Cost: $%.6f USD\n", cost);
}
#+end_src

*** Streaming
Claude Code supports streaming responses:

#+begin_src C
g_autoptr(AiClaudeCodeClient) client = ai_claude_code_client_new();

/* Connect to streaming signals */
g_signal_connect(client, "stream-start", G_CALLBACK(on_stream_start), NULL);
g_signal_connect(client, "delta", G_CALLBACK(on_delta), NULL);
g_signal_connect(client, "stream-end", G_CALLBACK(on_stream_end), NULL);

/* Start streaming chat */
ai_streamable_chat_stream_async(
    AI_STREAMABLE(client),
    messages,
    system_prompt,
    max_tokens,
    NULL,  /* tools */
    NULL,  /* cancellable */
    on_stream_complete,
    user_data
);
#+end_src

** CLI Invocation Details
*** Non-Streaming
#+begin_src sh
claude --print --output-format json \
    --model sonnet \
    --system-prompt "..." \
    --no-session-persistence \
    "user prompt"
#+end_src

*** Streaming
#+begin_src sh
claude --print --output-format stream-json --verbose \
    --model sonnet \
    "user prompt"
#+end_src

** Response Format
The Claude Code CLI returns JSON in the following format:

#+begin_src json
{
    "type": "result",
    "result": "response text",
    "session_id": "uuid",
    "usage": {
        "input_tokens": 100,
        "output_tokens": 50
    },
    "total_cost_usd": 0.001
}
#+end_src

** Comparison with AiClaudeClient
| Feature            | AiClaudeClient | AiClaudeCodeClient      |
|--------------------+----------------+-------------------------|
| Interface          | HTTP API       | CLI subprocess          |
| Authentication     | API key        | CLI config              |
| Session management | Manual         | Built-in                |
| Cost tracking      | Via usage      | Direct =total_cost_usd= |
| Tool use           | Full support   | Limited                 |
| Streaming          | SSE            | NDJSON                  |

** Error Handling
#+begin_src C
g_autoptr(GError) error = NULL;
g_autoptr(AiResponse) response = ai_cli_client_chat_sync(
    AI_CLI_CLIENT(client), messages, NULL, &error);

if (error != NULL)
{
    switch (error->code)
    {
        case AI_ERROR_CLI_NOT_FOUND:
            g_printerr("Claude CLI not found. Install it or set CLAUDE_CODE_PATH.\n");
            break;
        case AI_ERROR_CLI_EXECUTION:
            g_printerr("CLI execution failed: %s\n", error->message);
            break;
        case AI_ERROR_CLI_PARSE_ERROR:
            g_printerr("Failed to parse CLI output: %s\n", error->message);
            break;
        default:
            g_printerr("Error: %s\n", error->message);
            break;
    }
}
#+end_src

** Tool access

The client can grant the CLI its tools two ways.

#+begin_src c
/* The blanket bypass: --dangerously-skip-permissions */
g_object_set(client, "skip-permissions", TRUE, NULL);

/* Narrower: a permission mode plus an allow-list */
g_object_set(client,
             "permission-mode", "acceptEdits",
             "allowed-tools", "Read,Edit,Write",
             "additional-directories", "/srv/reference",
             NULL);
#+end_src

| Property | Flag | Notes |
|---+---+---|
| =skip-permissions= | =--dangerously-skip-permissions= | Wins if both are set, with a warning |
| =permission-mode= | =--permission-mode= | =acceptEdits=, =auto=, =bypassPermissions=, =manual=, =dontAsk=, =plan=. An unrecognised value warns and is omitted rather than passed through |
| =allowed-tools= | =--allowedTools= | Comma-separated in, one argv word per tool out |
| =disallowed-tools= | =--disallowedTools= | Same shape |
| =additional-directories= | =--add-dir= | For trees outside the working directory |
| =tools= | =--tools= | Which built-ins exist at all, as opposed to which are pre-approved |

** Session options
The rest of what =claude --print= accepts is exposed as GObject properties,
so bindings get them natively and the =ai= CLI reaches them through =--set=
without a flag per knob.

*** Agent and prompt
| Property                 | Flag                      | Notes                                                     |
|--------------------------+---------------------------+-----------------------------------------------------------|
| =agent=                  | =--agent=                 | Agent for this session                                    |
| =agents-json=            | =--agents=                | JSON object defining custom subagents                     |
| =append-system-prompt=   | =--append-system-prompt=  | *Adds to* the default prompt, where =system-prompt= replaces it; sent every turn, not only on session creation |
| =json-schema=            | =--json-schema=           | Constrains the reply to a JSON Schema                     |
| =autocompact=            | =--autocompact=           | =auto=, or 100k–1M tokens. Governs when the compaction that #AiClaudeCodeClient::context-compacted reports happens |

*** Models and budget
| Property           | Flag                | Notes                                                     |
|--------------------+---------------------+-----------------------------------------------------------|
| =fallback-model=   | =--fallback-model=  | Comma-separated list, tried in order when the primary is overloaded |
| =max-budget-usd=   | =--max-budget-usd=  | Spend ceiling for the run; 0 omits the flag. Formatted locale-independently, since claude parses it as a number |

*** Configuration and isolation
| Property                                  | Flag                                          | Notes                                          |
|-------------------------------------------+-----------------------------------------------+------------------------------------------------|
| =settings=                                | =--settings=                                  | Settings file path or JSON string              |
| =setting-sources=                         | =--setting-sources=                           | =user=, =project=, =local=. Use it to stop a run picking up settings from a repository it does not control |
| =strict-mcp-config=                       | =--strict-mcp-config=                         | Use *only* =mcp-config-path=; without it that flag is additive |
| =plugin-dirs= / =plugin-urls=             | =--plugin-dir= / =--plugin-url=               | Comma-separated; one flag per item. URLs are fetched and run — point them only at sources you trust |
| =tools=                                   | =--tools=                                     | Which built-ins exist at all, where =allowed-tools= decides which may run unattended |
| =betas=                                   | =--betas=                                     | Beta headers; API-key users only               |
| =disable-slash-commands=                  | =--disable-slash-commands=                    | Disables all skills                            |
| =bare=                                    | =--bare=                                      | Skips hooks, LSP, plugin sync, auto-memory and CLAUDE.md discovery. The most predictable way to run: the session sees what the client passed, not what the host has configured |
| =safe-mode=                               | =--safe-mode=                                 | All customizations off; auth, models, built-in tools and permissions still work |
| =exclude-dynamic-system-prompt-sections=  | =--exclude-dynamic-system-prompt-sections=    | Moves per-machine sections out of the system prompt. Worth setting for a fleet of identical runs: it is what lets them share a prompt cache |

*** Sessions, streaming and diagnostics
| Property                     | Flag                          | Notes                                             |
|------------------------------+-------------------------------+---------------------------------------------------|
| =continue-session=           | =--continue=                  | Pick up the directory's most recent conversation when no session id is known. An explicit id wins; persistence off suppresses it |
| =fork-session=               | =--fork-session=              | Branch a resumed conversation. Emitted alongside =--resume= or =--continue=, the only places claude accepts it |
| =include-partial-messages=   | =--include-partial-messages=  | Streaming only; gated on the output format because claude rejects it elsewhere |
| =include-hook-events=        | =--include-hook-events=       | Streaming only                                     |
| =forward-subagent-text=      | =--forward-subagent-text=     | Streaming only                                     |
| =debug= / =debug-filter=     | =--debug [filter]=            | A filter enables debug on its own, e.g. ="api,hooks"= or ="!1p,!file"= |
| =debug-file=                 | =--debug-file=                | Log to a file rather than stderr, so it does not disturb the parsed output |

#+begin_src C
g_object_set(client,
             "agent", "reviewer",
             "max-budget-usd", 5.0,
             "bare", TRUE,
             "tools", "Bash,Read,Edit",
             NULL);
#+end_src

Or from the CLI:

#+begin_example
$ ai -p claude-code --set agent=reviewer --set max-budget-usd=5 --set bare \
     "review the diff"
#+end_example

*The working directory is the boundary, not the permission mode.* Every mode
that can write can write anywhere the process can reach, so set
=AiCliClient:working-directory= to bound it:

#+begin_src c
ai_cli_client_set_working_directory(AI_CLI_CLIENT(client), "/srv/project");
#+end_src

Until recently that property had *no effect on this client*: it derives from
=AiCliClient=, whose spawn path applies the directory through a
=GSubprocessLauncher=, but this client built and spawned its own argv with a
bare =g_subprocess_newv()= at three sites and never created a launcher. A
caller that named a directory to bound what the CLI could reach got whatever
directory the parent process was started in. It is applied now.
