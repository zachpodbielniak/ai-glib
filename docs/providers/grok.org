* Grok Provider
xAI's Grok models, with real-time information access and strong reasoning capabilities.

** Configuration
*** Environment Variables
| Variable       | Description                   |
|----------------+-------------------------------|

*** Creating a Client
#+begin_src C
/* Using environment variable (recommended) */
g_autoptr(AiGrokClient) client = ai_grok_client_new();

/* Using explicit API key */
g_autoptr(AiGrokClient) client = ai_grok_client_new_with_key("xai-...");

** Example
#+begin_src C
#include <ai-glib.h>

static void
on_response(GObject *source, GAsyncResult *result, gpointer user_data)
{
    GMainLoop *loop = user_data;
    g_autoptr(GError) error = NULL;
    g_autoptr(AiResponse) response = NULL;

    response = ai_provider_chat_finish(AI_PROVIDER(source), result, &error);
    if (error != NULL)
    {
        g_printerr("Error: %s\n", error->message);
        g_main_loop_quit(loop);
        return;
    }

    g_autofree gchar *text = ai_response_get_text(response);
    g_print("Grok: %s\n", text);

    const AiUsage *usage = ai_response_get_usage(response);
    if (usage != NULL)
    {
        g_print("Tokens: %d in, %d out\n",
                ai_usage_get_input_tokens(usage),
                ai_usage_get_output_tokens(usage));
    }

    g_main_loop_quit(loop);
}

int main(void)
{
    g_autoptr(AiGrokClient) client = ai_grok_client_new();
    g_autoptr(AiMessage) msg = ai_message_new_user("What's happening in tech today?");
    g_autoptr(GMainLoop) loop = g_main_loop_new(NULL, FALSE);
    GList *messages = g_list_append(NULL, msg);

    ai_provider_chat_async(AI_PROVIDER(client), messages,
                           NULL, 4096, NULL, NULL, on_response, loop);

    g_main_loop_run(loop);
    g_list_free(messages);
    return 0;
}
#+end_src

** API Compatibility
Grok uses an OpenAI-compatible API:

- *Endpoint*: =https://api.x.ai/v1/chat/completions=
- *Authentication*: Bearer token
- *Request Format*: OpenAI-compatible messages format
- *Response Format*: OpenAI-compatible choices format

** Features
- *Chat Completion*: Full support
- *Streaming*: Full support via =AiStreamable= interface
- *Tool Use*: Full support for function calling
- *Vision*: Supported on vision models
- *Real-time Info*: Access to X (Twitter) data
- *System Prompts*: Full support
- *Image Generation*: Imagine generation and edits via =AiImageGenerator=
- *Video Generation*: Text, image and reference generation via =AiVideoGenerator=

** Tool Calling
Grok's API is OpenAI-compatible, so ai-glib uses the same wire-format serializer as the OpenAI client. See the [[file:openai.org#tool-calling][OpenAI Tool Calling section]] for the details --- the behavior is identical: tool definitions wrapped in ={type:"function", ...}=, prior assistant tool calls round-tripped as =tool_calls=, and tool results emitted as separate =role:"tool"= messages.

** Image Generation
=AiImageGenerator= supports generation and JSON editing. The current defaults and complete capability matrix are listed under “Imagine image and video APIs” below. =AI_GROK_IMAGE_DEFAULT_MODEL= resolves to =AI_GROK_IMAGE_MODEL_GROK_IMAGINE_2_0=. Existing Imagine and retired Grok 2 image constants remain source-compatible.

*** Image Generation Example
#+begin_src C
#include <ai-glib.h>

static void
on_image_complete(GObject *source, GAsyncResult *result, gpointer user_data)
{
    GMainLoop *loop = user_data;
    g_autoptr(AiImageResponse) response = NULL;
    g_autoptr(GError) error = NULL;

    response = ai_image_generator_generate_image_finish(
        AI_IMAGE_GENERATOR(source), result, &error);

    if (error != NULL)
    {
        g_printerr("Error: %s\n", error->message);
        g_main_loop_quit(loop);
        return;
    }

    AiGeneratedImage *image = ai_image_response_get_image(response, 0);
    ai_generated_image_save_to_file(image, "grok-output.png", NULL);
    g_print("Image saved!\n");

    g_main_loop_quit(loop);
}

int main(void)
{
    g_autoptr(AiGrokClient) client = ai_grok_client_new();
    g_autoptr(AiImageRequest) request = ai_image_request_new(
        "a robot playing chess in a park"
    );
    g_autoptr(GMainLoop) loop = g_main_loop_new(NULL, FALSE);

    /* Model is optional - defaults to grok-imagine-image-2.0 */
    ai_image_request_set_model(request, AI_GROK_IMAGE_MODEL_GROK_IMAGINE);

    ai_image_generator_generate_image_async(
        AI_IMAGE_GENERATOR(client),
        request,
        NULL,
        on_image_complete,
        loop
    );

    g_main_loop_run(loop);
    return 0;
}
#+end_src

* Imagine image and video APIs
=AiGrokClient= implements both =AiImageGenerator= and =AiVideoGenerator=. Images default to =AI_GROK_IMAGE_MODEL_GROK_IMAGINE_2_0=; videos default to =AI_GROK_VIDEO_MODEL_GROK_IMAGINE_1_5=. Existing image and video model constants remain available. Authentication uses =XAI_API_KEY= or =GROK_API_KEY= through the existing client configuration.

** Image capability matrix
| Feature | Imagine image 2.0 | Imagine image / quality | Grok 2 Image legacy |
| Generation count | 1–10 | 1–10 | 1–10 |
| JSON image editing | yes | yes | no |
| Reference images | up to 5 | up to 5 | none |
| Aspect ratio | documented ratios | documented ratios | omitted |
| Resolution | 1k / 2k | 1k / 2k | omitted |
| Quality | auto / low / medium | omitted | omitted |
| Response | URL or base64 | URL or base64 | URL or base64 |

Adding reference images automatically selects the edits endpoint; explicit =AI_IMAGE_OPERATION_EDIT= requires a reference. The wire representation is JSON, including base64 data URLs. Four-kilopixel output and unsupported image 2.0 quality values fail before HTTP dispatch. Unsupported OpenAI size/style fields are not serialized. Reference labels are folded into the prompt for image editing, video reference images and the video starting frame; the caller’s original prompt remains unchanged.

#+begin_src bash
ai -p grok --image-gen --resolution 2k --aspect 16:9 -o lake.png 'A lake at dawn'
ai -p grok --image-gen --ref lake.png -o painting.png 'Restyle as an oil painting'
ai -p grok --video-gen --duration 8 --resolution 1080p -o lake.mp4 'A lake at dawn'
ai -p grok --video-gen --video-op image-to-video --ref lake.png --duration 8 -o animated.mp4 'Slow camera pan'
ai -p grok --video-gen --video-op reference-to-video --ref lake.png --resolution 720p -o reference.mp4 'Explore this landscape'
#+end_src

** Video request and transport
Construct =AiVideoRequest= with a prompt and set its operation to =generate=, =image-to-video=, or =reference-to-video=. Supply one =AiImage= via =ai_video_request_set_image()= for image-to-video, or up to seven images via =ai_video_request_add_reference_image()= for reference-to-video. Video 1.5 supports up to three preset voice identifiers via =ai_video_request_set_voices()=; reference-to-video may consist entirely of voices. Call =ai_video_generator_generate_video()= or its async/finish pair, then save the resulting =AiVideoResponse= with =ai_video_response_save_to_file()=.

Duration accepts 1–15 seconds; the default is left to the server. Resolutions are 480p/720p, plus 1080p for video 1.5 text/image generation. Reference video is capped at 720p. =generate-audio= is a tri-state: unset follows the service default, false requests silence, true explicitly requests audio. The default poll interval is one second and the overall deadline ten minutes, both configurable per request.

All requests capture the caller's thread-default context. Owned timeout sources and cancellation handle both pending polls and active network requests. Cancellation stops local waiting; it does not cancel or refund a submitted remote job. Initial job creation is not retried automatically, preventing duplicate generation charges after an ambiguous network failure. Transient polling failures follow the configured HTTP retry policy within the overall deadline. Failed, expired, malformed and moderation-rejected results are errors, not empty success responses.

** Specification and limitations
The exact official HTTP reference and model guides used for this implementation are downloaded under =docs/specs/= with source URLs, SHA-256 checksums and reconciliation notes in [[file:../specs/xai-imagine-provenance.org][Imagine specification provenance]]. The public video API covers generation, image animation, references and preset voices; video editing/extension, last-frame constraints, custom audio, uploaded file IDs and persistent storage configuration are not exposed. Output URLs are temporary: save the media promptly. Loopback tests verify wire behavior without paid live calls.
