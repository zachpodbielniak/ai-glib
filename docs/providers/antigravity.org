* Antigravity Provider
The Antigravity provider (=AiAntigravityClient=) wraps Google's =agy= CLI in
headless print mode. It is the agentic counterpart to talking to Gemini
over HTTP: this one drives the coding agent, with its tools, sessions,
permissions and sandbox.

** Overview
| Property      | Value                          |
|---------------+--------------------------------|
| Type          | =AI_PROVIDER_ANTIGRAVITY=      |
| Name          | "Antigravity"                  |
| Default Model | =gemini-3.7-flash-high=        |
| Interface     | CLI (subprocess)               |
| Binary        | =agy=                          |
| Aliases       | =antigravity=, =agy=           |

** Requirements
- The =agy= CLI must be installed and authenticated (run =agy= interactively once)
- The CLI must be available in =$PATH= or named via =AGY_PATH=

** Environment Variables
| Variable   | Description                               |
|------------+-------------------------------------------|
| =AGY_PATH= | Override the path to the =agy= executable |

The CLI's own credentials are read by =agy= itself, not by ai-glib.

** How the prompt is delivered
The prompt is *not* passed as =agy --print <prompt>=. =--print= consumes
the next argv word, so =agy --print --model X= would send ="--model"= as
the prompt, and a positional prompt would hit =MAX_ARG_STRLEN= on a long
conversation.

Instead the client always runs:

#+begin_example
agy --input-format stream-json --output-format stream-json --model <id> ...
#+end_example

and pipes one NDJSON user event on stdin:

#+begin_example
{"event":"user","message":{"content":"<the flattened prompt>"}}
#+end_example

That is the documented stdin protocol, and it is why the prompt never
appears in argv. =--disable-slash-commands= is on by default so a library
caller's prompt is treated as text — text that happens to begin with =/=
must not be expanded as a slash command.

agy has no system-prompt flag. On a fresh session the system prompt is
inlined at the start of that content, wrapped in =<system>= tags (the same
shape OpenCode uses). A resumed or =--continue= session already carries it
and does not see it again.

The conversation is flattened into that single prompt: user messages
verbatim, assistant messages prefixed =Previous assistant response:=, joined
with blank lines, and a trailing instruction to always produce a text
summary rather than ending on tool calls.

Every one is a real GObject property, so bindings get native syntax and
=notify::= signals; =ai --set= reaches them with no extra plumbing.

agy's own =--print-timeout= defaults to 5 minutes, which is shorter than
the library's 30-minute process bound. The client therefore always emits
the flag, formatted from =process-timeout-ms= (1800000 → =30m=) unless
=print-timeout= is set explicitly.

** Signals
The streaming signals are declared on =AiCliClient= and emitted by this client:

| Signal         | Arguments      | When                             |
|----------------+----------------+----------------------------------|
| =stream-start= | —              | Before the first text delta      |
| =delta=        | =const gchar*= | Each =text_delta=                |
| =stream-end=   | =AiResponse*=  | At EOF, with the assembled response |

Tool start/finish are reported on the =::event= stream as
=AI_EVENT_TOOL_STARTED= / =AI_EVENT_TOOL_FINISHED=, keyed by
=step-<index>=. agy runs its own tools inside the CLI; they are not
executed by =AiToolExecutor=.

** Usage
*** Basic Usage
#+begin_src C
#include <ai-glib.h>

int main(void)
{
    g_autoptr(AiAntigravityClient) client = ai_antigravity_client_new();
    g_autoptr(AiMessage) msg = ai_message_new_user("Hello!");
    GList *messages = g_list_append(NULL, msg);

    ai_provider_chat_async(
        AI_PROVIDER(client),
        messages,
        NULL,
        4096,
        NULL,
        NULL,
        on_chat_complete,
        user_data
    );

    g_list_free(messages);
    return 0;
}
#+end_src

*** Reasoning Effort
agy accepts exactly =low=, =medium= and =high=.

#+begin_src C
ai_cli_client_set_effort_level(AI_CLI_CLIENT(client), "high");
#+end_src

=xhigh= and =max= have no agy equivalent, so they fold onto =high=.
Anything else is dropped with a message rather than passed through.

*** Permissions, mode and extra directories
#+begin_src C
ai_antigravity_client_set_skip_permissions(client, TRUE);

g_object_set(client,
             "mode", "plan",
             "sandbox", TRUE,
             "additional-directories", "/srv/a,/srv/b",
             "agent", "reviewer",
             NULL);

ai_cli_client_set_working_directory(AI_CLI_CLIENT(client), "/srv/scratch");
#+end_src

Valid =mode= values are =accept-edits= and =plan=. An unknown mode is
dropped, with a message saying so.

*** Sessions
Session persistence is on by default. The first call starts a conversation
and captures =conversation_id= from the result; subsequent calls resume it
with =--conversation=, and the system prompt is not re-sent.

#+begin_src C
const gchar *sid = ai_cli_client_get_session_id(AI_CLI_CLIENT(client));

ai_cli_client_set_session_persistence(AI_CLI_CLIENT(client), FALSE);
#+end_src

To pick up the most recent conversation without knowing its id, set
=continue-session=:

#+begin_src C
g_object_set(client, "continue-session", TRUE, NULL);
#+end_src

An explicit session id wins. Persistence being off suppresses both.
From the CLI this is =ai -p antigravity -c= or =ai -p agy -c=.

*** Entering from a provider switch
An =AiAntigravityClient= selected by
=ai_conversation_set_provider()= has its =session-id= and
=continue-session= cleared. Its first switched turn starts a fresh agy
conversation and receives the completed portable =AiMessage= history in the
stdin user event. Tool calls and results in that history are projected as
labelled text.

The switch does not import agy's conversation store or combine it with
=--continue=. A =conversation_id= captured from the new turn may be resumed
normally afterwards. The conversation working directory and a compatible
tool endpoint are applied; local ai-glib tools are disabled because agy runs
its own tools.

See [[file:../provider-switching.org][Provider switching]] for details and
projection limits.

** Wire format
Non-streaming and streaming both request =--output-format stream-json=,
because =--input-format stream-json= requires it. =parse_json_output=
extracts the terminal =result= event (or a bare json envelope if that is
what stdout carried).

A successful envelope:

#+begin_src json
{
  "conversation_id": "...",
  "status": "SUCCESS",
  "response": "the answer\n",
  "usage": { "input_tokens": 10, "output_tokens": 4, "...": 0 }
}
#+end_src

=status= other than =SUCCESS= (=ERROR=, =CANCELED=, =INTERRUPTED=,
=INVALID=, =WAITING=, =RUNNING=) becomes =AI_ERROR_CLI_EXECUTION= using
the =error= field. agy can print that envelope and still exit 0, so the
parser is consulted before the exit status.

The stream is NDJSON:

#+begin_src json
{"event":"init","conversation_id":"...","init":{...}}
{"event":"step_update","step_update":{"step_type":"agent_response","text_delta":"...","state":"ACTIVE"}}
{"event":"step_update","step_update":{"step_type":"tool","tool_name":"run_command","state":"DONE","tool_info":{...}}}
{"event":"result","result":{"status":"SUCCESS","response":"...","conversation_id":"...","usage":{...}}}
#+end_src

Unrecognised events are skipped. A =result= with =status= other than
=SUCCESS= fails the turn.

** Image generation through =generate_image=
=AiAntigravityClient= implements =AiImageGenerator=. It asks the authenticated =agy= agent to invoke its native =generate_image= tool once and returns the generated artifact as an =AiGeneratedImage= containing base64 bytes and the detected MIME type. This uses the CLI account's quota; no Gemini API key is required.

#+begin_src sh
ai --list-image-models -p agy
ai --image-gen -p agy --aspect 16:9 "a mountain lake at sunrise"
ai -I -p antigravity -o landscape.jpg "a mountain lake at sunrise"
#+end_src

The default output filename follows the returned MIME type. An explicit =-o= path does not transcode the bytes: naming a JPEG =picture.png= does not turn it into PNG. PNG, JPEG, GIF and WebP signatures are recognized.

*** Library API
Use the same synchronous or asynchronous interface as the HTTP providers:

#+begin_src C
#include <ai-glib.h>

int
main(void)
{
	g_autoptr(AiAntigravityClient) client = ai_antigravity_client_new();
	g_autoptr(AiImageRequest) request = ai_image_request_new("a mountain lake at sunrise");
	g_autoptr(AiImageResponse) response = NULL;
	g_autoptr(GError) error = NULL;
	AiGeneratedImage *image;

	/* The aspect ratio is a prompt hint; agy controls final dimensions. */
	ai_image_request_set_aspect_ratio(request, "16:9");
	response = ai_image_generator_generate_image(AI_IMAGE_GENERATOR(client), request, NULL, &error);
	if (response == NULL)
	{
		g_printerr("Image generation failed: %s\n", error->message);
		return 1;
	}

	/* Bytes remain valid independently of agy's on-disk artifact. */
	image = ai_image_response_get_image(response, 0);
	if (!ai_generated_image_save_to_file(image, "landscape.jpg", &error))
	{
		g_printerr("Saving image failed: %s\n", error->message);
		return 1;
	}
	return 0;
}
#+end_src

For asynchronous use, call =ai_image_generator_generate_image_async()= and collect the response with =ai_image_generator_generate_image_finish()=. The work runs off the calling thread; completion and the =image-progress= signal run on the initiating thread-default context when the result is collected. =GCancellable= and =process-timeout-ms= bound the subprocess through the existing CLI transport helper.

*** Model selection and capabilities
The request's model (=-m= in =ai=) selects the agent that invokes the image tool, not the image-generation backend. It defaults to the client's =model= property, then =AI_ANTIGRAVITY_DEFAULT_MODEL=. The response's model field records that agent model. =agy= controls the underlying image model. Discovery lists the known agent models with the same image-tool capabilities; newer valid =agy --model= identifiers may also be used.

| Capability | Behavior |
|------------+----------|
| Text-to-image | One native =generate_image= call per request |
| Aspect ratio | Passed as a prompt hint; exact dimensions are not guaranteed |
| Count | One image; larger counts clamp to one under normal validation |
| References, editing, variation, upscale | Not supported by this adapter; rejected before spawning |
| Size, quality, format, transparency, seed | Not exposed; unsupported knobs are dropped by normal validation |
| Strict validation | Call =ai_image_request_validate()= with the default model descriptor and =AI_IMAGE_VALIDATE_STRICT= to reject unsupported settings |
| Partial previews | Not supported |

Validation and launch preparation copy the request. The caller's original request is unchanged. CLI properties such as =skip-permissions=, =sandbox=, =agent=, =print-timeout=, working directory and child environment retain their normal meaning. Image calls always start a fresh conversation and do not use or update =session-id= or =continue-session=.

*** Permissions, artifacts and failures
The normal =agy= permission policy applies. Image generation does not enable =skip-permissions= automatically. If local policy requires review for =generate_image=, allow that tool in agy's configuration or explicitly use the existing =--skip-permissions= CLI option (the =skip-permissions= GObject property). Headless permission denials are errors.

Current =agy= stream events can omit the output pathname even after successful generation. The adapter assigns a unique =ImageName=, requires a matching completed =generate_image= event and a successful terminal result in the same UUID conversation, then searches only =~/.gemini/antigravity-cli/brain/<conversation-id>/= for that name's artifacts. A per-client =HOME= environment override selects the corresponding store. Returned prose paths are never opened. Files must be recent, regular, unlinked to other files, no larger than 64 MiB, and carry a recognized raster signature; symlinked conversation directories and files are rejected. Multiple matching images are treated as an ambiguous result. Original artifacts remain in agy's store.

A terminal chat status of =SUCCESS= alone is insufficient: the image tool may have failed while the agent successfully explained that failure. Tool errors, nonzero process exits, missing completion events and missing readable artifacts all return =GError=. The adapter does not automatically retry paid generations. Changes to agy's event schema, artifact naming or store location may require updating this adapter.

The protocol follows [[https://antigravity.google/docs/cli/headless/][Antigravity's headless mode documentation]]; artifact behavior was checked against the locally installed CLI on 2026-09-11.

When the selected agent model ends in =-low=, =-medium= or =-high=, that encoded effort takes precedence and the adapter omits =--effort=. This avoids agy rejecting the high default model together with the base client's medium default. For other model names, the normal =effort-level= property is forwarded.
