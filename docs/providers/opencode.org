#+title: OpenCode CLI provider
#+description: Headless OpenCode options, event translation, lifecycle and compatibility tests

* Supported contract

=AiOpenCodeClient= wraps =opencode run --format json=. Audited against the installed OpenCode *1.18.29* binary and its versioned implementation on 2026-09-11. Both synchronous and asynchronous chat and streaming are supported. OpenCode performs its own model calls and tool execution; ai-glib owns the subprocess, input projection, event translation, cancellation and deadline.

The executable resolves through =executable-path=, then =OPENCODE_PATH=, then =opencode= on =PATH=. Configure model-provider credentials in OpenCode as usual. Server attachment credentials are separate from model API keys.

* Options

Every applicable headless =run= option is available as a GObject property. Scalar properties are reachable from =ai --set NAME=VALUE=. The =file-paths= string vector is intended for C and language bindings; =files= retains the scalar CLI interface.

| Property | OpenCode option | Behavior |
|----------+-----------------+----------|
| =model= | =--model= | Arbitrary =provider/model= ID; defaults to =AI_OPENCODE_DEFAULT_MODEL= |
| =effort-level= | =--variant= | Arbitrary provider-defined variant; default =medium=; empty string omits it |
| =agent= | =--agent= | Agent profile |
| =command= | =--command= | Named command; last user message is passed as literal command arguments |
| =session-id= | =--session= | Explicit native session; takes precedence over continue |
| =continue-session= | =--continue= | Continue the most recent session when no explicit ID is set |
| =fork-session= | =--fork= | Only emitted with an explicit session or continue |
| =share= | =--share= | Requests session sharing; false by default |
| =title= | =--title= | Nonempty session title; otherwise OpenCode derives one |
| =files= | =--file= | Legacy comma-separated paths; trims whitespace and ignores empty entries |
| =file-paths= | =--file= | String vector preserving commas and spaces; appended after =files= |
| =attach= | =--attach= | URL of an existing OpenCode server |
| =username= | =--username= equivalent | Child =OPENCODE_SERVER_USERNAME=; never argv |
| =password= | =--password= equivalent | Child =OPENCODE_SERVER_PASSWORD=; never argv |
| =working-directory= | Local cwd and =--dir= | Local process directory; relative local paths are canonicalized for =--dir= |
| =directory= | =--dir= | Overrides only OpenCode's directory, independently of local cwd; useful for remote attachment |
| =port= | =--port= | Local server port; zero leaves selection to OpenCode |
| =thinking= | =--thinking= | Enables completed reasoning events |
| =skip-permissions= | =--auto= | Approves requested permissions while preserving explicit denies |
| =pure= | =--pure= | Disables external plugins |
| =log-level= | =--log-level= | =DEBUG=, =INFO=, =WARN= or =ERROR=; invalid values are reported and omitted |
| =print-logs= | =--print-logs= | OpenCode diagnostics on stderr |
| =process-timeout-ms= | Library deadline | Per subprocess, including async retries and model discovery; 30 minutes by default; zero disables |

=--format json= is owned by the transport. =--interactive= and the hidden interactive/replay/demo options are deliberately excluded: they require terminal UI and conflict with the JSON protocol. =--help= and =--version= are inspection commands, not model turns. Hidden =--yolo= and =--dangerously-skip-permissions= aliases are represented by the canonical =skip-permissions= / =--auto= mapping.

Setting =username= or =password= to NULL restores inheritance from the caller's environment. An empty string is an explicit empty override. Do not put a real password in a shell's =--set password= argument; use =OPENCODE_SERVER_PASSWORD= or set the GObject property in the embedding application.

** Permission correction

The provider formerly injected =OPENCODE_PERMISSION={"*":"allow"}= alongside =--auto=. That overrides configured denial rules and is not equivalent to OpenCode's documented auto-approval. The provider now emits only =--auto= and preserves the caller's =OPENCODE_PERMISSION=. Older binaries without =--auto= are outside this audited contract.

** Remote attachment and local files

Use =working-directory= for the local files and =directory= for the remote project. The launcher also updates =PWD= because OpenCode consults it when resolving local attachments. A remote path need not exist locally:

#+begin_src C
/* The local cwd and the server's project path are independent. */
g_object_set(client,
	"attach", "http://localhost:4096",
	"working-directory", "/home/user/local-files",
	"directory", "/srv/remote-project",
	"username", "opencode",
	NULL);
#+end_src

OpenCode 1.18.29 uploads local regular files to an attached server; it rejects local directories without a shared filesystem and files larger than 10 MiB. Those errors are propagated from the binary. For local execution OpenCode resolves file references itself.

* Prompt and command handling

Chat input is piped through stdin, keeping long conversations below argv limits. Portable history is projected to text; the system prompt is wrapped in =<system>= tags on a new native session because OpenCode has no separate system-prompt flag. Resumed sessions already carry their system context. A plain-text completion instruction is appended for ordinary chat.

=command= changes the meaning of stdin: the last user message supplies exact arguments, without system tags, previous messages or the completion instruction. An ordinary prompt beginning with =/name= is *not* a named-command invocation in =opencode run=. Use =command=name= explicitly. Terminal-only commands such as interactive session management are not headless commands. =AiConversation='s local built-ins still run locally; its passthrough behavior does not synthesize =--command=.

#+begin_example
ai -p opencode --set command=test "src/example.c --verbose"
ai -p opencode --set agent=build --set pure --set thinking "explain this function"
ai -p opencode --set attach=http://localhost:4096 --set directory=/srv/project "inspect the tests"
ai -p opencode --dry-run "hi"
#+end_example

* Models

=ai_provider_list_models_async()= executes the installed binary's =opencode models= and returns its configured =provider/model= IDs. Discovery has cancellation, deadline and exit-status handling; the list no longer advertises a stale static selection. The command uses local OpenCode configuration even when =attach= is set: it is not the remote server's model catalogue. OpenCode may refresh its own model cache according to its configuration; ai-glib does not force =--refresh=.

The =AI_OPENCODE_MODEL_*= constants in [[file:../../src/providers/ai-opencode-client.h][the public header]] remain source-compatible convenience strings, not availability guarantees. Arbitrary model IDs can be supplied through =model=. Retired model constants remain defined so old source continues to compile.

* Response and event translation

OpenCode writes NDJSON with =type=, =timestamp=, =sessionID= and usually =part=. Both output parsers use type-checked accessors; unrelated plugin output and unknown events are ignored rather than treated as fatal protocol changes.

| Wire event | Library behavior |
|------------+------------------|
| =step_start= | Captures session identity; no premature turn completion |
| =text= | Appends =part.text=; streaming emits =AI_EVENT_TEXT_DELTA= |
| =reasoning= | Streaming emits =AI_EVENT_THINKING_DELTA=; requires =thinking= |
| =tool_use= | Streaming emits tool start and completed/error result with the input and output |
| =step_finish= | Adds step-local input/output counts and dollar cost to turn totals; records stop reason |
| =error= | Fails the turn, even with exit status zero or missing error details |

These are *completed parts*, not token-by-token deltas from OpenCode: text and reasoning become visible when the CLI emits the finished part. Reasoning remains separate from user-visible text. =AiResponse= has no reasoning-content or cache-token breakdown type; nonstreaming output contains text, and =AiUsage= exposes the sums of OpenCode's =input= and =output= fields. Cost is taken directly from OpenCode, in micro-dollars, so cache and reasoning pricing is not recomputed from those two counts.

Tool identity prefers =part.callID= (the model call ID); =part.id= is a distinct OpenCode part ID and is only a fallback. Completed and failed tools each emit start and finish so consumers can display tool lifecycles consistently. The =sessionID= on an event, or a part when the top-level field is absent, is retained when =session-persistence= is enabled.

=step_finish.reason= maps =length= to max tokens, =content-filter= to content filtering, =tool-calls= to tool use, and =error= to an error stop reason; normal completion maps to end of turn. A subsequent step updates the stop reason without resetting accumulated usage or cost. Integer totals saturate instead of wrapping on malformed or excessive counts.

An error payload may be a string, an object with =message=, or OpenCode's ={name, data: {message}}= shape. Structured errors take precedence over generic process diagnostics, but emitted text never makes a nonzero exit successful. All three execution modes check process success.

** Tool-only fallback and lifecycle

For compatibility, async chat can request one plain-text summary after a tool-only turn, provided it captured a session ID. The retry preserves model, variant, agent, cwd, remote directory, attachment server, credentials, permissions and global execution flags. It resumes the captured session without re-forking, re-sharing, re-running a named command or re-attaching the original files. A failed best-effort summary falls back to the original tool summary. Cancellation and deadline errors are returned, not converted to fallback text. A later empty response never reuses an earlier turn's tool summary.

Synchronous chat retains the tool-only parser result; streaming exposes tool events directly. The summary retry is specific to async chat. Cancellation and deadlines kill the child and close pending communication; each async source belongs to the initiating thread-default context and is destroyed by pointer on completion.

* MCP endpoints and provider switching

OpenCode has no =--mcp-config=. =AI_ENDPOINT_KIND_MCP_CONFIG_OPENCODE= is delivered through =OPENCODE_CONFIG=, with OpenCode's ={mcp: {name: {type: "local", command: [...], environment: {...}}}}= schema. The caller's previous setting is restored on revocation. The Claude-shaped MCP endpoint kind is rejected.

Local MCP configuration cannot be injected into an already running attached server; that combination is rejected instead of pretending tools were delivered. Configure the remote server separately. =OPENCODE_CONFIG_CONTENT= is intentionally not used for host-tool injection because its precedence would override project settings.

On a conversation provider switch, portable completed history enters a fresh native session; =session-id= and =continue-session= are cleared. Subsequent turns may resume the newly captured ID. See [[file:../provider-switching.org][provider switching]], [[file:../native-session.org][native session context]], [[file:../tools.org][host tools]], and [[file:../events.org][normalized events]].

** API limits and native launch

OpenCode has no =--max-tokens= flag, so =max_tokens= is not translated into a run option. Model output limits belong to OpenCode configuration. The =tools= argument is not a set of local callbacks for this provider; use the MCP endpoint mechanism for host tools. Generic inline image content is not converted into =--file= attachments by this provider; use explicit file paths when the selected OpenCode model supports them.

=ai --launch-cmd-print= and the corresponding =ai-tui= mode also map the command, directory and attachment properties to native =opencode run= options. Command output refuses credential property overrides that differ from inherited environment values, so it cannot print a new secret. Interactive launch remains governed by OpenCode's terminal options and rejects unsupported headless properties. All native launch modes preserve explicit permission denies.
