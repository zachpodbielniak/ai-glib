* Reconciliation
The REST video field listing omits =generate_audio=, but the video-generation capability page documents it explicitly and includes a REST curl example sending false. ai-glib follows that explicit example. Similarly, image 2.0 =quality= appears in the image-generation guide (auto/low/medium), although the REST field listing omits it. The provider gates quality on image 2.0.

The Markdown rendition omits some warning callout contents. The rendered reference-to-video page states seven reference images, three preset voices, and a maximum 720p resolution; the rendered Imagine overview states five reference images for image editing. These model limits are enforced locally. Video duration is 1–15 seconds; 1080p applies to video 1.5 text/image generation. Image generation count is 1–10.

* Implemented projection
Image generation uses =POST /v1/images/generations=; any input reference selects =POST /v1/images/edits= with =image: {url: data-URL}= for one reference or =images: [{url: data-URL}, ...]= for several. The library does not send OpenAI multipart bodies to Imagine.

Video generation submits =POST /v1/videos/generations= and polls =GET /v1/videos/{request_id}= until done, failed, expired, cancellation, or the request deadline. Image-to-video uses =image=; reference-to-video uses =reference_images= and optional =reference_audios= voice identifiers. The initial POST is never automatically retried because it is not idempotent. Poll GETs use the existing bounded HTTP retry mechanism, and the total deadline cancels both I/O and polling waits.

* Scope
This version exposes text/image/reference video generation and preset voices. Video editing/extension, exact last-frame pinning, custom audio clips, Files API IDs, storage options and signed output uploads are outside the public video request contract. Local image bytes are encoded as data URLs. Temporary output URLs must be saved promptly. Tests use loopback HTTP; no paid live generation was performed.
