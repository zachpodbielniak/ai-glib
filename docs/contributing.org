* Contributing to ai-glib
Thank you for your interest in contributing to ai-glib!

** Development Setup
*** Prerequisites
- GCC with gnu89 support
- GLib >= 2.56
- libsoup >= 3.0
- json-glib >= 1.6
- GObject Introspection (optional, for bindings --- built with =make GIR=1=)
- PyGObject (=python3-gobject= / =python3-gi=) --- optional, used only by =make test-gi= (the binding smoke test skips cleanly if absent)

*** Fedora
#+begin_src sh
dnf install gcc make glib2-devel libsoup3-devel json-glib-devel \
            gobject-introspection-devel
#+end_src

*** Ubuntu/Debian
#+begin_src sh
apt install build-essential libglib2.0-dev libsoup-3.0-dev \
            libjson-glib-dev gobject-introspection
#+end_src

*** Building
#+begin_src sh
git clone https://gitlab.com/your-username/ai-glib.git
cd ai-glib
make
make test
#+end_src

** Code Style
*** C Standard
- Use =gnu89= exclusively
- Compile with =gcc=

*** Formatting
- *Indentation*: TAB (4 spaces width)
- *Naming conventions*:
  - Types: =AiTypeName= (PascalCase)
  - Functions: =ai_type_name_method()= (lowercase_snake_case)
  - Macros/defines: =AI_MACRO_NAME= (UPPERCASE_SNAKE_CASE)
  - Variables: =lowercase_snake_case=
- *Comments*: Always use =/* comment */=, never =//=

*** Function Style
#+begin_src C
/* Function declaration */
AiResponse *
ai_client_chat_sync(
    AiClient     *self,
    GList        *messages,
    GCancellable *cancellable,
    GError      **error
);

/* Function definition */
AiResponse *
ai_client_chat_sync(
    AiClient     *self,
    GList        *messages,
    GCancellable *cancellable,
    GError      **error
){
    g_autoptr(AiResponse) response = NULL;

    g_return_val_if_fail(AI_IS_CLIENT(self), NULL);

    /* implementation */

    return (AiResponse *)g_steal_pointer(&response);
}
#+end_src

*** Memory Management
Always use GLib's automatic cleanup:

#+begin_src C
/* Use g_autoptr for GObjects */
g_autoptr(AiClaudeClient) client = ai_claude_client_new();
g_autoptr(AiMessage) msg = ai_message_new_user("Hello");
g_autoptr(GError) error = NULL;

/* Use g_autofree for strings */
g_autofree gchar *text = ai_response_get_text(response);

/* Use g_steal_pointer for ownership transfer */
return (AiResponse *)g_steal_pointer(&response);
#+end_src

*** GObject Introspection
All public APIs must include GIR annotations:

/**

** Adding a New Provider
1. Create header and source files:

   - =src/providers/ai-<name>-client.h=
   - =src/providers/ai-<name>-client.c=

2. Extend the right base class and implement the interfaces:

   - =AiClient= for an HTTP provider, =AiCliClient= for a wrapper around a
     command-line tool (see below)
   - =AiProvider= interface
   - =AiStreamable= interface (for streaming support)

3. Update build system:

   - Add to =PUBLIC_HEADERS= in Makefile
   - Add to =LIB_SOURCES= in Makefile

4. Register the provider by name --- every one of these is a hand-written
   switch or table, so a missed one fails silently (usually by falling back
   to a different provider):

   - =AiProviderType= in =src/core/ai-enums.h= --- *append*, the values are
     ABI
   - the =GEnumValue= table, =_to_string= and =_from_string= in
     =src/core/ai-enums.c=
   - =provider_name_map[]= in =src/core/ai-config.c= (the YAML key, which is
     underscored)
   - the switch in =ai_simple_create_provider()=
   - =bin/ai.c=: the =--provider= help text, =make_provider()=,
     =list_providers()=, and (for CLI providers) =dry_run()=

5. Add tests:

   - Create =tests/test-<name>-client.c=
   - Add the name round-trip to =tests/test-enums.c= and a factory check to
     =tests/test-simple.c=

6. Add documentation:

   - Create =docs/providers/<name>.org=
   - Add it to the tables in =docs/providers/index.org=, =docs/index.org=,
     =docs/configuration.org= and =docs/cli.org=

7. Update umbrella header and forward declarations:

   - Add =#include "providers/ai-<name>-client.h"= to =src/ai-glib.h=
   - Add the typedef to =src/ai-types.h=

*** CLI Providers
A provider that wraps a command-line tool derives from =AiCliClient= and
overrides five vfuncs: =get_executable_path=, =build_argv=, =build_stdin=,
=parse_json_output= and =parse_stream_line=. The base class supplies the
whole synchronous pipeline (resolve the binary, build argv, pipe stdin,
spawn with a timeout, check the exit status, parse), so a subclass usually
only implements the async and streaming paths itself.

Three conventions are worth copying rather than reinventing:

- *Pipe the prompt, do not pass it.* =build_argv= emits a placeholder
  program token at index 0 which the caller overwrites with the resolved
  path; the prompt goes through =build_stdin=. Putting a conversation in
  argv hits =ARG_MAX= and puts it in =ps= output.
- *Expose the argv builder through a private =-internal.h=* (guarded on
  =AI_GLIB_COMPILATION=, and *not* in =PUBLIC_HEADERS=) so tests and
  =ai --dry-run= can assert the exact command without spawning anything.
- *Do not trust the exit status alone.* CLIs vary in whether a rejected
  argument is a non-zero exit, a JSON error payload, or both; parse the
  output first. =AiGrokBuildClient= is the worked example --- grok exits 0
  on some errors.

** Testing
*** Running Tests
#+begin_src sh
make test              # Run all tests
make test-verbose      # Run with verbose output
#+end_src

*** Running Specific Tests
#+begin_src sh
./build/release/tests/test-config
G_TEST_VERBOSE=1 ./build/release/tests/test-message
#+end_src

*** Sanitizers
#+begin_src sh
make DEBUG=1 ASAN=1 UBSAN=1 test
#+end_src

Builds under =build/debug/= coexist with the release tree, so switching
back needs no rebuild.

*** Testing a CLI Provider
Provider tests split in two, and both matter:

- *Unit* --- call the vfuncs directly. Non-static builders can be called by
  name (=ai_<name>_client_build_argv=); static ones are reachable through
  =AI_CLI_CLIENT_GET_CLASS(client)->build_argv=. Assert the argv, the piped
  prompt, and the parsers against real captured payloads, including
  malformed and wrong-typed ones.
- *Subprocess* --- point =executable-path= at a stub shell script that
  records its argv, cwd and stdin and prints a staged response. This is the
  only way to prove the prompt actually reaches the child, that the working
  directory is applied, and that the sync, async and streaming paths agree.
  =tests/test-grok-build-subprocess.c= is the worked example.

Note that GTest makes warnings fatal, so a test that exercises a
=g_warning= path must wrap it:

#+begin_src C
g_test_expect_message(NULL, G_LOG_LEVEL_WARNING, "*unknown effort level*");
argv = build_argv(...);
g_test_assert_expected_messages();
#+end_src

*** Writing Tests
Tests use GLib's GTest framework:

#+begin_src C
static void
test_message_new_user(void)
{
    g_autoptr(AiMessage) msg = ai_message_new_user("Hello");

    g_assert_nonnull(msg);
    g_assert_cmpint(ai_message_get_role(msg), ==, AI_ROLE_USER);

    g_autofree gchar *text = ai_message_get_text(msg);
    g_assert_cmpstr(text, ==, "Hello");
}

int main(int argc, char *argv[])
{
    g_test_init(&argc, &argv, NULL);

    g_test_add_func("/ai-glib/message/new-user", test_message_new_user);

    return g_test_run();
}
#+end_src

** Submitting Changes
1. Fork the repository
2. Create a feature branch: =git checkout -b feature/my-feature=
3. Make your changes following the code style
4. Add tests for new functionality
5. Ensure all tests pass: =make test=
6. Commit with clear messages
7. Push and create a merge request

** Commit Messages
- Use present tense: "Add feature" not "Added feature"
- Use imperative mood: "Fix bug" not "Fixes bug"
- Keep first line under 72 characters
- Reference issues when applicable

Example:

#+begin_example
Add streaming support for Gemini provider

Implement the AiStreamable interface for AiGeminiClient to enable
real-time streaming of responses.

Closes #42
#+end_example
