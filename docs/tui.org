* The =ai-tui= front-end
=ai-tui= drives any ai-glib provider from a terminal, showing prose,
reasoning and grouped tool calls as they happen. It is what
[[file:cli.org][the =ai= CLI]] is for one-shot prompts, but for sitting in.

Everything about *what* a conversation is --- how calls group, how a summary
reads, which run of bytes is a filename --- lives in
[[file:transcript.org][the view layer]]. This binary turns a style role into
an ncurses attribute, puts characters on a screen, and reads keys. That is
the whole of it, and it is deliberate: an Emacs front-end replaces this one
file and shares everything else.

** Synopsis
#+begin_src sh
ai-tui [-p PROVIDER] [-m MODEL] [-s SYSTEM] [OPTIONS] [PROMPT]
echo "PROMPT" | ai-tui [OPTIONS]
#+end_src

#+begin_src sh
ai-tui -p claude-code -m opus
ai-tui "review the diff"
echo "review the diff" | ai-tui
#+end_src

The prompt comes from leftover arguments if present, otherwise from stdin when stdin is not a terminal --- the same rule as [[file:cli.org][the =ai= CLI]]. On a terminal, that text is the first turn: it is placed in the composer and sent. A piped prompt is read, then stdin is reopened on =/dev/tty= so ncurses can take the keyboard. Without a terminal --- stdout is not a tty, or =/dev/tty= cannot be opened --- the same prompt runs one turn and prints the transcript, as =--dump= does. Use =--= before a prompt that begins with a dash.

** Herdr integration

Inside a herdr pane, =ai-tui= automatically reports itself as =ai-tui= with =idle=, =working= and =blocked= states, including local tool approval waits. It uses the injected local socket directly and needs no installed hook or wrapper. =--no-herdr= disables reporting. Native launch and informational modes remain unregistered. See [[file:herdr.org][Native herdr integration]] for detection, child hook ownership, failure handling, tests and the limits of recovery after a server restart.

** Independent Defaults
Run =ai --setup= and select scope =2= to configure =ai-tui=. Startup resolves =apps.ai-tui.default_provider= and =apps.ai-tui.default_model= independently of =ai= and the library's top-level defaults. =AI_GLIB_DEFAULT_PROVIDER= and =AI_GLIB_DEFAULT_MODEL= do not affect this scope. Omitted options behave exactly like =ai-tui -p default -m default=: use saved ai-tui defaults and ignore =AI_PROVIDER=. A saved model is used only when its provider matches the startup selection. Runtime provider switches do not inherit the startup model or reapply these defaults. See [[file:cli.org][the setup protocol]] and [[file:configuration.org][the exact schema]].

** CLI Process Deadline
CLI providers default to =process-timeout-ms=0= in =ai-tui=, including after runtime provider switches, so the wrapper does not terminate a long-running turn after thirty minutes. At startup, =--set process-timeout-ms=600000= opts into a ten-minute deadline; =--set process-timeout-ms=0= explicitly disables it. As with other startup =--set= properties, an explicit override is not reapplied after a provider switch. Cancellation remains available. The library default remains 1800000 ms; HTTP, native CLI and tmux-specific timeouts are separate controls.

** Restoring Native Session History
With =-c= / =--continue=, the transcript is populated before the first screen is drawn, without submitting a prompt or starting the wrapped CLI. This also applies when the saved provider default is one of the supported wrappers. Previous user turns are available through input history. =--dump= includes the restored transcript before the new turn.

- =grok-build= reads Grok's native =updates.jsonl=. Tool calls use grok's wire names (=read_file=, =search_replace=, =run_terminal_command=), including ACP history variants such as =ReadFile=, so restored groups read as =Read file.c, edited parser.c, ran make= rather than =Used N tools=.
- =codex-cli= / =codex= reads Codex rollout JSONL under =$CODEX_HOME/sessions= (defaulting to =~/.codex/sessions=). Completed user, reasoning, assistant, command and file-change items are folded; restored groups use the live names (=command_execution=, =file_change=) so they read as =Ran make, changed file.c=.
- =claude-code= and =claude-tmux= read =~/.claude/projects/<cwd-with-slashes-as-dashes>/<id>.jsonl= (or =CLAUDE_CONFIG_DIR= / tmux's =claude-project-dir=). User turns, thinking, assistant text and =tool_use= / =tool_result= pairs are folded.
- =cursor= reads =~/.cursor/projects/<cwd-without-leading-slash>/<id>/<id>.jsonl= under =agent-transcripts=. =<user_query>= wrappers are stripped so the composer history is the prompt, not Cursor's timestamp envelope.
- =opencode= reads =$XDG_DATA_HOME/opencode/opencode.db= (defaulting to =~/.local/share/opencode/opencode.db=). Top-level sessions for this working directory are selected; subagent rows with a parent id are skipped.
- =antigravity= / =agy= reads =~/.gemini/antigravity-cli/cache/last_conversations.json= to map the cwd onto =brain/<id>/.system_generated/logs/transcript.jsonl=, then folds =USER_INPUT= / =PLANNER_RESPONSE= / =tool_calls=.

Session selection is restricted to the provider's working directory and uses the most recent native activity timestamp. =--set session-id=ID= selects that session explicitly. The selected ID is passed back to the CLI (=--resume= for Grok, Claude and Cursor, =resume ID= for Codex never =--last=, =--session= for OpenCode, =--conversation= for Antigravity) so the next turn continues the history shown on screen. Historical prompts and tools are only rendered, never submitted or executed again. A fresh startup without a resume option does not load history, and =--set session-persistence=false= disables restoration.

The reader honors =GROK_HOME= / =CODEX_HOME= / =CLAUDE_CONFIG_DIR= / =XDG_DATA_HOME= and =HOME= environment overrides, including Grok's hashed directory buckets. Missing sessions leave a fresh transcript. Unreadable or malformed selected logs produce a visible error without adding partial history; logs over 64 MiB are rejected with a visible display-limit error. Native launch and dry-run modes do not load history.

** What it looks like
*** Native CLI Alternative
=ai-tui --launch= opens the underlying provider's own interactive interface instead of initializing ncurses or the ai-glib conversation. =--launch-cmd= prints that native command, and =--launch-cmd-print= prints its noninteractive text-output equivalent; neither command-printing option executes anything. Optional positional text is passed literally as an initial prompt. All three modes use ai-tui's independent saved provider/model defaults, including =-p default -m default=.

#+begin_src bash
ai-tui --launch -p claude -m opus
ai-tui --launch -p default -m default --skip-permissions
ai-tui --launch -p default -m default "Continue implementing authentication"
ai-tui --launch-cmd-print -p codex-cli "review this change"
#+end_src

See [[file:cli.org::*Native CLI Launch][native CLI launch]] for supported providers, shell quoting, stdin, credentials, native option limitations, and executable overrides. Launch modes cannot be combined with =--dump=, =--dry-run=, =--local-tools=, or =--yes=.

*** ai-glib Harness
The interface uses Catppuccin Mocha by default: a high-contrast identity badge, two-tone wordmark, mauve composer frame, contrasting session panel, readable tool states, and highlighted completion rows. Message-role badges and slim gutter rails separate your prompts from assistant prose. The header names the provider, working directory and active theme; the activity strip reports the model, current work and elapsed time. An empty session shows a short getting-started view instead of a blank transcript.

#+begin_example
 ai / Grok Build                                      catppuccin-mocha
 /home/zach/source/projects/ai-glib

   YOU
   > build phase 1

   ASSISTANT
   Now the codec registry.

   Created 2 files  +5-0

 Grok Build / grok-4.6   your turn · type to reply
 ╭─ YOUR TURN ─────────────────────────────────────────────────────╮
 │ Your turn · type a reply, or / commands  @ files                │
 ╰───────────────────────────────────────────────────────── 1/1 ───╯
 RET send | C-f find | C-o help | C-t theme | C-p panel

#+end_example

The bottom keybinding hints use Emacs notation: =RET= is Return, =M-RET= is Alt-Return, =C-g= is Control-g, and =S-RET= is Shift-Return. =TAB=, =ESC=, and =<up>= name the Tab, Escape, and up-arrow keys.

The alternation is the point. Narration, a collapsed group of what the model
actually did, more narration --- rather than a wall of tool output with the
explanation lost inside it.

The session panel appears at widths of at least 110 columns and heights of at least 20 rows. It shows the provider/model, theme, latest reported usage, up to three todos, agent states, and tool/approval mode when space permits. Panel values wrap at word boundaries, including long model names, usage reports, and agent identifiers; todos and agents use hanging bullets so continuation lines remain grouped with their entry. Text stops above the shortcut footer; =/todos=, =/running= and =/tools= provide full listings. =C-p= toggles the panel, and that choice survives narrowing and widening the terminal. Below 32 columns or nine rows, a resize notice replaces the interface and preserves the draft. Nothing requires a Nerd Font. In non-UTF-8 locales, composer borders and the wordmark fall back to ASCII.

*** Whose turn it is
A finished turn and a slow one look alike on a quiet screen: the sweep stops either way and nothing on the screen says the harness is now waiting on a person. So the composer states it. When a turn hands control back --- answered, stopped by =C-c=, or failed --- the composer frame turns from the accent color to the confirmation color, its title changes from =COMPOSE= to =YOUR TURN=, the placeholder line reads =Your turn · type a reply=, and the status strip reads =your turn · type to reply= in place of =ready=.

The frame also breathes for about 2.5 seconds as the turn is handed over: the border alternates weight on a slow beat, three times, and then stops. Weight and not geometry or color, so the layout never moves under a cursor you are about to type at, and bounded rather than perpetual, for the same reason startup and feedback accents are bounded --- a session left open overnight must not be repainting a terminal. What remains after the breath is static, and it is the color and the two labels that carry the state from then on. =--no-animation= drops the breath and keeps all of it.

The state is derived rather than remembered, so it always describes what is actually true: it ends the moment there is anything in the composer, and it returns if you clear the line again without sending. A search or approval overlay is its own, louder request for input and owns the frame while it is up. Terminals without color show the waiting frame in bold, since a state nobody can see is not a state.

*** Motion and feedback
A brief startup sweep introduces the composer. While a turn runs, a small two-tone highlight travels along the composer's top border alongside the existing activity spinner. It never covers the prompt, shifts the layout, or delays text and keyboard input. Search and approval overlays suppress the border sweep. Once the turn finishes, the border briefly indicates success, failure, or cancellation, and the status strip names the outcome. Theme and panel changes also give short status feedback without adding messages to the transcript or model context.

Motion is deliberately bounded: startup lasts 900 ms, feedback lasts about 1.6 seconds, the turn hand-off breathes for about 2.5 seconds, and an idle session has no ongoing animation timer. The activity and effect clock is shared, and cached transcript rows are reused rather than rebuilt for animation ticks. =--no-animation= disables the startup/border sweeps and spinner rotation; elapsed time still updates once per second and static feedback remains available. There are no blinking text effects, palette changes, or moving transcript contents.

*** Themes
Use =--theme NAME= to select =catppuccin-mocha=, =catppuccin-latte=, =nord=, =terminal=, or =monochrome=. =--list-themes= lists the available names without constructing a provider or requiring a terminal. =C-t= cycles themes in the running interface without interrupting the conversation or discarding a draft.

#+begin_src bash
ai-tui --theme catppuccin-mocha
ai-tui --theme catppuccin-latte --no-animation
AI_TUI_THEME=nord ai-tui
NO_COLOR=1 ai-tui
ai-tui --list-themes
#+end_src

Theme selection is =--theme=, then =AI_TUI_THEME=, then Catppuccin Mocha. An unknown name is an error with a hint to list valid themes. =NO_COLOR= disables colors unless =--theme= explicitly requests them; pressing =C-t= is also an explicit color choice. =monochrome= always disables color. Live choices are session-local: set =AI_TUI_THEME= in your environment for a persistent preference. These visual settings do not affect provider properties or =--set=.

On 256-color terminals the RGB palettes are mapped to the nearest stable xterm color-cube/grayscale entries; ai-tui never mutates the user's terminal palette. The =terminal= theme retains the terminal's background and standard colors. Lower-color terminals use standard colors, and terminals without color support retain bold and reverse-video selection. Theme surfaces and selection colors cover blank cells as well as text. =--no-animation= replaces the animated spinner with a stationary marker, while elapsed time still updates once per second. None of the chrome or color escapes appears in =--dump= output.

one that refuses to start.

*** Searching and following
=C-f= opens a separate, append-only search field. Type a case-sensitive substring; matching rendered rows are highlighted and the view jumps to the first match. =Enter= or =Down= advances, =Up= or =Shift-Enter= goes back, and navigation wraps. =Backspace= edits the query and =C-u= clears it. =Escape= or =C-f= closes search and restores the untouched draft. The result count is matching rows, not occurrences; text hidden inside a collapsed block is not searched until expanded, and a match does not span a wrap boundary.

=PgUp= and =PgDn= scroll incrementally rather than jumping straight to the bottom. Scrolling away pauses following even if a turn completes while you read. =C-l=, sending a prompt, or reaching the bottom with =PgDn= resumes following. Search and history remain in memory only; the redesign does not persist prompts to disk. Existing explicit export/save commands still do so.

*** Writing more than one line
=Alt-Enter= inserts a newline and works everywhere. =Shift-Enter= does the
same *where the terminal encodes it distinctly* --- a plain terminal sends
the same carriage return for =Shift-Enter= as for =Enter=, which is why
every harness that binds the two differently ships a terminal-setup step.
ai-tui does not require one: it registers the two sequences a configured
terminal produces (the kitty keyboard protocol's =CSI 13;2u= and xterm's
=modifyOtherKeys= =CSI 27;2;13~=), so =Shift-Enter= works if your terminal
sends either and costs nothing if it does not.

The framed composer grows as you type, up to ten content rows or the available terminal height. Longer drafts scroll to keep the cursor visible; =C-a= and =C-e= reveal the beginning and end. The frame reports the current row and total rows when space permits. Unicode input is accepted, including wide characters; byte offsets remain compatible with the library's completion APIs. Complex emoji/grapheme display still depends on the terminal's width rules.

*** Composer editing

| Key | Action |
|-----+--------|
| =Delete= | Delete the next Unicode character without moving the cursor |
| =C-w= | Kill preceding whitespace and then the preceding word |
| =C-k= | Kill from the cursor to the next newline or draft end; at a newline, kill that newline |
| =C-y= | Insert the most recently killed text at the cursor |

Words are separated by Unicode whitespace, so filenames and punctuation stay together. Delete and word kill move across whole Unicode code points, not grapheme clusters. The single kill buffer lasts for this process only; each nonempty =C-w= or =C-k= replaces it, while an empty kill preserves it. =Backspace=, =Delete= and =C-u= do not replace the kill buffer. Yank inserts text literally, including newlines, and closes completion without submitting a prompt. These bindings edit the draft during a running turn too; approval and search prompts retain their own key handling.

Bracketed paste is enabled while ai-tui owns the terminal. A multiline paste is inserted into the composer without submitting any of its lines; press =Enter= explicitly when ready. Terminals without bracketed paste support cannot distinguish a pasted newline from a typed =Enter=, so use =C-g= for multiline text there. Pasted approval answers are ignored: approvals require a deliberate key. Control characters other than newlines and tabs are discarded in bracketed input; tabs are displayed as a single blank but retained in the prompt.

Pressing =Enter= during a running turn preserves the entire draft instead of discarding it; the composer is labeled =DRAFT / waiting for turn=. This is not an automatic send queue. The draft remains for you to submit after the turn ends. Navigating back down past the newest history item also restores the draft you were editing.

*** =C-c= takes one thing at a time
First close an active search or deny a pending approval; otherwise stop the turn, close the completion menu, throw away the
half-written line, and only then --- pressed twice inside a second and a
half, with nothing left to interrupt --- leave.

Every step short of the last is recoverable, which is the point. The key
somebody reaches for to stop a runaway answer should not also be the key
that ends the session and loses the conversation with it. While a =C-c=
is armed the status bar says =^C again to quit=; let it lapse and the
next one starts over rather than quitting.

=C-d= on an empty line quits outright, as it does in a shell, and =/quit=
works when no turn is in flight; use =C-c= to cancel a running turn first.

Note that =C-c= reaches ai-tui as =SIGINT= rather than as a keystroke:
=cbreak()= leaves =ISIG= on, so the terminal driver signals before
ncurses sees the byte. Handling it as a signal is what keeps =C-z= and
flow control working, which =raw()= would take away.

*** =C-g=: write it in your editor
Writes the current prompt to a temporary =.md= file, hands the terminal
to =$VISUAL= or =$EDITOR=, and takes back whatever was saved. =VISUAL=
wins because that is what the two mean: it is the full-screen one, and
this needs a screen. Both are parsed as command lines, so =EDITOR="emacs
-nw"= works.

*Quitting the editor without saving leaves the prompt alone.* A non-zero
exit is how somebody says they changed their mind, and the file on disk
may be a half-finished draft --- reading it back anyway would make the
cancel do the opposite of cancelling.

One trailing newline is stripped, since every editor that ends a file
properly adds one. Interior blank lines are kept exactly as written.

The external editor runs synchronously, so ai-glib's main loop pauses until it exits. A wrapped process may continue until pipe backpressure stops it; local asynchronous work cannot advance during that pause. Terminal size and bracketed paste mode are restored on return. Invalid UTF-8 from the editor is rejected without replacing the draft.

Scrolling away from the bottom stops the view following new output; the
status bar says =[scrolled]= while that is so. Sending, or scrolling back
down, resumes following.

** Tool previews
Edits and commands now show compact inline previews beneath the grouped summary without requiring expansion. =C-n= selects a tool group and =C-b= expands it for more detail. Read/search calls remain summarized in compact mode. A compact group previews relevant calls among its last four calls and names how many earlier calls are hidden; expanded groups list every call.

*** Edit regions
Recorded =old_string=/=new_string= pairs (including OpenCode's =oldString=/=newString=) are rendered as a line diff with two lines of surrounding context. A red =-= gutter and green =+= gutter identify removals and additions without forcing the entire source line into one color. The two number columns refer to lines within the supplied old/new snippets, *not absolute file line numbers*. Unchanged gaps between hunks are explicitly marked. Newline-only changes are noted separately.

#+begin_example
Edited demo.c, ran make -j4  +1-1 >
  Edit demo.c
    @@ edit region; relative old/new lines @@
    -    1      | static int answer(void) { return 1; }
    +         1 | static int answer(void) { return 2027; }
  Bash make -j4
    $ make -j4
      | Compiling demo.c
      | Linking demo
#+end_example

Keywords, strings, comments, numbers, types and callable names use distinct theme roles. In Catppuccin Mocha these use mauve, green, muted subtext, peach, yellow and blue respectively; changing themes with =C-t= recolors existing previews immediately. Monochrome retains the textual diff gutters and line numbers.

The language-aware lexical highlighter recognizes C/C++, JavaScript/TypeScript, Rust, Go, Python, shell/Makefile, JSON, YAML, Lisp/Elisp, Haskell and SQL by filename. It preserves multiline comment/string state within supplied snippets, including context hidden by the preview. It is not a compiler or semantic highlighter; constructs requiring a full parser and context outside the supplied snippet cannot be inferred. Unknown extensions use plain literal-code styling.

Multi-edit arrays, unified diffs, =apply_patch= envelopes, Grok =search_replace= replacements, and Codex =file_change= entries containing diffs are supported. Supplied patch hunk headers are preserved rather than replaced with invented coordinates. Pending, failed and denied edits say the requested change is not confirmed successful. A write with only new content is labeled as having no previous snapshot; a provider that supplies only filenames gets an explicit unavailable-preview message. Rendering never rereads files or runs =git diff=, so later filesystem changes cannot silently rewrite the history.

Codex =exec --json= normally supplies only filenames and change kinds. For successful =file_change= events without a diff, the Codex adapter captures =git diff HEAD= for each affected path when the event is received. These previews are explicitly labeled as working-tree diffs that may include earlier changes; they are not exact per-tool patches. Newly added files without a tracked diff use their current contents with a separate no-baseline label. Existing provider diffs take precedence, failed changes are not supplemented, and unavailable Git context keeps the unavailable-preview message. Multi-file patches count distinct paths in the summary. Completed file-change snapshots refresh earlier previews, even when prose has already closed the tool group.

Fallback capture uses literal path arguments, disables external diff drivers and textconv, and is bounded to eight entries, 64 KiB per patch, and a shared one-second deadline per event. Git is a runtime dependency for this fallback. Captured previews remain stable if files change again; expanding a preview never launches Git or reads the filesystem.

*** Commands and output
Each preview shows the recorded command after =$=, preserving up to six command lines, followed by the first six output lines. Empty, pending and denied results are distinguished. Expanding a group raises the output allowance to 64 lines per call. Preview text comes from the normalized tool result; if a provider supplies no result yet, the UI says it is waiting rather than inventing output. Grok Build's Anthropic-shaped =user= tool-result events now feed this path, including string and text-block-array results.

*** Limits and safety
Compact edit previews allow twelve diff rows per call; expanded previews allow 64. Inputs are bounded to 64 KiB and 256 lines before diffing, with at most eight entries from a multi-edit or file-change array. Long source/output lines show at most 320 UTF-8-safe bytes followed by a truncation marker. These are logical-line limits: narrow terminals may wrap them into additional screen rows. Truncated previews explicitly say more exists; expansion increases the row allowance but does not remove the byte/line safety bounds. ANSI CSI/OSC sequences and unsafe control bytes are removed from preview payloads, tabs display as four spaces, and invalid UTF-8 becomes replacement characters. The original tool result remains unchanged.

=--dump= includes the same compact previews as plain text, without ANSI styling. No preview text is added to the model's conversation. The shared =AiViewToolBlock:show-previews= property provides the same rendering to other frontends; see [[file:transcript.org][the view-layer contract]].

** Completion
The menu opens as you type. A =/= at the start of the line lists every
command, skill and agent, and each character after it narrows the list;
an =@= anywhere lists paths.

| Key                | Does                                            |
|--------------------+-------------------------------------------------|
| =Up= / =Down=      | Move the highlight, wrapping at both ends       |
| =PgUp= / =PgDn=    | Move it a page at a time                        |
| =Tab=              | Take what is on offer, or step to the next      |
| =Shift-Tab=        | Step back                                       |
| =Enter=            | Submit an exact command, otherwise accept the candidate |
| =Escape=           | Dismiss, until the line changes again           |

The arrows, =PgUp= and =PgDn= belong to the menu while it is showing and
to the input history and the transcript when it is not --- one key, two
jobs, decided by what is on screen. Press =Escape= first if you want the
history back with a half-typed command still on the line.

A fully typed command such as =/model= or =/provider= runs on the first =Enter= when the highlighted completion already matches the entire command. Partial names still complete first: =/prov= followed by =Enter= fills in =/provider=, leaving it in the composer so you can add an argument. =Tab= always completes without submitting. Path completions also remain in the composer.

=Home= / =C-a= and =End= / =C-e= refresh completion at the new cursor position, just like the arrow keys. Before the initial slash there is no token to complete, so =Tab= leaves the draft unchanged. Terminal tests exercise every registered built-in with one =Enter=, including missing-argument feedback, and check that these local commands never invoke the provider.

Numeric Home/End escape sequences used by tmux and other terminals are recognized alongside the terminfo defaults, preventing their bytes from being inserted into the command text.

Each row is the name in bold, its description in readable secondary text, and the harness it
came from right-aligned --- the origin has its own column because the
description is what gets truncated, and the origin is the half that tells
two same-named commands apart.

=Tab= inserts a single candidate outright. With several it inserts their
common prefix if that adds anything, and steps the highlight otherwise
--- so the first =Tab= makes progress and the second is a choice rather
than a repetition. Directories carry a trailing slash, so one more =Tab=
walks into them.

Mentions and command names are highlighted as you type, using the same
scanner the pipeline uses. A mention that will not resolve still lights
up --- it is a candidate, and you can see it was noticed.

None of this is decided here: =ai_completion_context_query()= returns the byte
range to replace and the candidate list, and this program does the
replacing. An Emacs frontend will call the same function. See
[[file:harness.org][the harness layer]].

** Commands
The built-ins, plus every command, skill and agent found in the
directories the other harnesses use. =/help= lists all of it with origins.

| Command             | Does                                              |
|---------------------+---------------------------------------------------|
| =/help=             | Every command, skill and agent, and the keys      |
| =/clear=            | Empty the transcript, the history and the todos   |
| =/reset=            | Start a fresh session and return to the splash screen |
| =/quit=             | Exit                                              |
| =/model [NAME]=     | Show or switch the model without restarting       |
| =/provider [NAME]=  | Show or switch the provider, preserving context   |
| =/tools=            | The tools the model can call                      |
| =/commands=         | Commands from disk, and what shadows what         |
| =/skills=           | Skills                                            |
| =/agents=           | Agents                                            |
| =/reload=           | Rescan the search paths                           |
| =/cwd [PATH]=       | Show or change the working directory              |
| =/todos=            | The current todo list                             |
| =/running=          | Background agents, and what they are doing        |
| =/kill ID\vert all=      | Stop a background agent, or every one             |
| =/expand LINE=      | What a line would send, without sending it        |
| =/save PATH=        | Write the transcript to a file                    |
| =/export FMT [PATH]= | Write it as =text=, =markdown= or =org=         |

*** Command paths

=/cwd=, =/save= and =/export= resolve relative paths against the conversation's current directory. Consecutive relative directory changes therefore build on one another, and subsequent saves land in the directory shown in the header. Absolute paths remain absolute; =~= and a leading =~/= expand to your home directory. Paths are literal: spaces need no quotes, and shell variables, wildcards and =~otheruser= are not expanded. =/export= accepts spaces or tabs between its format and path. An invalid directory leaves the current directory unchanged; failed writes report the error in the transcript. Saving to an existing file replaces its contents.

#+begin_example
/cwd ~/source/projects
/cwd ai-glib
/save review notes.txt
/export org review notes.org
#+end_example

The process directory is unchanged so background work is not redirected. The conversation directory is propagated through the existing provider, tool and completion APIs. Terminal regression tests exercise nested relative changes, home expansion, paths containing spaces, failed directory changes and write errors; editing tests submit the resulting drafts to a local stub provider without network access.

*** Other command behavior

=/agents= and =/running= are different things: the first lists agent
*definitions* found on disk, the second lists agents actually running.

Anything else is a command file: =/deploy staging= runs
=~/.claude/commands/deploy.md= with =staging= as =$1=. See
[[file:commands.org][authoring them]].

=/clear= empties the *local* view. A provider holding a session of its own
--- the CLI wrappers do --- is not affected; clearing the transcript does
not un-say what was already said to it.

*** Resetting the session

=/reset= discards the entire active conversation and returns to the fresh-launch splash screen with an empty composer. It removes the transcript, model message history, recalled input lines, saved draft, kill buffer, todos, tool approval memory, background-agent results, search state, selection and turn feedback. Background agents are cancelled and detached before their cleanup completes, so late results cannot reappear in the new conversation. The next turn uses a fresh tool executor and background-agent brigade.

CLI providers also lose their =session-id= and =continue-session= setting, including when launched with =-c= or =--set session-id=ID=. The next prompt starts a new native session instead of resuming the previous conversation. Provider-owned session files and databases on disk are retained; =/reset= removes history from the active TUI session, not the provider's archive.

The current provider, model, system prompt, working directory, provider options, streaming and local-tool settings remain selected. Theme and panel preferences remain as configured. Like other built-ins, =/reset= runs when the foreground turn is idle; press =C-c= to stop a running turn first. With =--no-expand=, slash commands are sent literally to the provider, including =/reset=.

Terminal regression tests compare =/clear= and =/reset= against a local CLI stub, verify that resume flags and old prompts disappear, exercise repeated resets and history/yank keys, and send another turn after reset. A =--dump /reset= test covers execution without curses initialization.

*** Switching providers
With no argument, =/provider= reports the current provider. With a name, it
changes the provider for the next turn and keeps the completed in-process
conversation:

#+begin_example
> Remember the word amber.
I will remember amber.

> /provider openai
Provider switched to OpenAI. Context preserved.

> What word did I ask you to remember?
amber
#+end_example

Use the same names as =-p=, including =claude-code=, =claude-tmux=,
=opencode=, =grok-build=, =antigravity= / =agy= and =cursor=. The target uses
its default model; use =/model NAME= afterwards to change it.

The command runs only while no turn is in flight. A construction or migration
failure says =Provider unchanged: ...= and leaves the old provider selected.
The transcript, system prompt, working directory and completed message
history survive. If the target is a CLI wrapper, local tools are turned off
and the TUI says so.

A switched-to CLI always starts a fresh native session: any target
=session-id= and =continue-session= are cleared. Startup =-c= / =--continue=
does not apply to a later =/provider= command, and neither do startup
=--set= overrides.

**** Carrying a wrapped CLI's own history
Leaving =claude-code=, =claude-tmux=, =codex-cli= or =grok-build= reads that
program's own transcript and carries it to the next provider, so the tool
calls the CLI made in its own process --- which the TUI never saw --- are
not lost with the switch:

#+begin_example
> /provider claude
Provider switched to Claude. Context preserved.
Carried 12.4 KiB of that session's own history, including its tool calls.
#+end_example

The line appears only when something was actually carried. Nothing on disk
yet, or a provider whose history lives in SQLite (=opencode=, =cursor=,
=antigravity=), switches quietly on the portable history alone.

This migration is handled by =AiConversation=, including when ai-tui has an MCP host enabled. Terminal regression tests inspect the receiving CLI's actual system prompt and message input to verify that the original system instructions, portable conversation, and harvested native tool history survive a provider switch; they also check that a subsequent =/model NAME= reaches the child's model argument.

The carried text goes into the system prompt, which the transcript never
shows, so =/context= is how to see it:

#+begin_example
> /context
Carrying 12.4 KiB of history from a previous provider, sent with every
turn. /context clear drops it.

> /context clear
Carried context dropped. Later turns send only this session's own history.
#+end_example

Dropping it is worth doing when the import is large and no longer relevant:
it is sent with *every* turn, not just the first.

*** Changing the model
=/model= with no argument reports the current model; with one it changes it
for the next turn and keeps everything else:

#+begin_example
> /model claude-opus-5
Model switched from claude-sonnet-5 to claude-opus-5. Context preserved.
#+end_example

Like =/provider=, it is refused while a turn is in flight --- half a turn
answered by one model and half by another is not a transcript anybody can
reason about afterwards.

The name is not validated here, because no wrapped CLI offers a validating
lookup. An id the provider will reject fails on the *next* turn, which is
why the change is reported rather than applied silently.

See [[file:provider-switching.org][Provider switching]] for the exact
migration table and limits, and [[file:native-session.org][Native session
import]] for what the carried history contains.

*** Skill discovery
The =/= menu discovers =.agents/skills/<name>/SKILL.md= relative to the working directory and =~/.agents/skills/<name>/SKILL.md=; flat =<name>.md= files work too. These are the source of truth: project =.agents= wins over home =.agents=, and both win over same-named skills in other harness directories. Unique skills from the other common locations remain available, with one menu entry per name. A frontmatter =name:= overrides the filename-derived name used for deduplication. Built-ins and explicit commands retain their existing priority over skills with the same slash name.

Filesystem watches refresh the menu automatically, including nested skill edits, additions, deletions and roots created after startup; no restart or extra keystroke is needed. =/reload= remains available for a manual rescan. This changes discovery and menu precedence, not the native skill resolution of wrapped CLI providers.

For locally resolved skills, =/skill-name additional context= sends both the skill instructions and the complete trailing request, including when the skill has no argument placeholders. This also applies to =echo '/skill-name additional context' | ai-tui=. Use =/expand /skill-name additional context= to inspect the prompt without sending it, or =ai-tui --dump '/skill-name additional context'= to force a noninteractive turn.

*** When a command is not found
=/commands= with nothing to show prints every directory it searched,
which is the answer to the question you are about to ask. If a file is
there but another one won, the same listing prints the winner's path.

*** CLI providers handle their own
claude-code, opencode, grok, antigravity and cursor resolve =@=, =/= and their own skills
themselves, so with one of those selected a line reaches the child
exactly as typed and =/compact= still means what it means to them. The
built-ins above still run locally --- the wrapped tool has no opinion
about this program's transcript.

=--no-expand= turns the pipeline off entirely, for the case where the
text must reach the model verbatim.

** Mentions
=@path= pulls a file in. The prompt keeps its shape and the files follow
it, so a one-line question is not buried under the file it named.

#+begin_example
  > explain @src/core/ai-event.c and @src/core/ai-event.h
#+end_example

A directory expands to a listing, a binary file is named but not inlined,
and a path that does not exist is left exactly as written --- which is
what makes an email address or a Python decorator harmless. Use =/expand=
to see the result before sending it.

** While a turn is running
The status bar shows what the turn is doing, with a spinner and the time
so far:

#+begin_example
  Grok Build / grok-4.6   ⠹ Running make test… (5s · ^C to stop)
#+end_example

The phrase tracks the turn --- =Waiting for the model=, =Thinking=,
=Reading ai-event.c=, =Running make test=, =Responding= --- so a long
tool call is visibly a long tool call rather than a program that might
have hung. The elapsed time is what separates a slow turn from a stalled
one.

The words come from =AiConversation:activity=; only the animation lives
here. See [[file:transcript.org::*Showing progress][Showing progress]].

A provider that emits no events (claude-tmux reads a finished transcript
rather than a stream) shows =Waiting for the model= throughout, which is
honest, and is the case where the indicator earns its keep.

** Tool approval
With =--local-tools= against an HTTP provider, tools run in this process and
each call is offered for approval:

#+begin_example
 run Bash: rm -rf build/ ?  [y]es  [n]o  [a]lways  [d]eny all
#+end_example

| Answer      | Does                                                        |
|-------------+-------------------------------------------------------------|
| =y=         | Run this call                                               |
| =n=         | Refuse it; the model is told, and usually tries something else |
| =a=         | Run it, and stop asking about this tool for the rest of the run |
| =d=         | Refuse and abort the turn                                   |

=--yes= approves everything without asking, which is what you want for an
unattended run and not much else.

Refusing one call does not end the turn. The model is told the tool was
denied and generally acknowledges it and tries another route, which is more
useful than a turn that simply stops --- only =d= stops everything. An
answer of =a= is remembered for that run only: consent given about one task
is not consent for the next.

*This never appears for the CLI wrapper providers.* claude-code, opencode,
grok-build, antigravity and cursor run their own tools inside their own processes, and their
approval is =--skip-permissions= and the per-provider =permission-mode= and
=allowed-tools= properties, not this. =--local-tools= is refused for them,
with a note saying so, rather than silently doing nothing.

** =--dump=, and testing
#+begin_src sh
ai-tui -p grok-build --dump "list the files here"
ai-tui -p grok-build "list the files here"
echo "list the files here" | ai-tui -p grok-build
#+end_src

A prompt without a terminal --- leftover arguments or a pipe, with stdout
captured or no controlling tty --- runs one turn and prints the transcript
as plain text. =echo PROMPT | ai-tui= at a real terminal is interactive:
the pipe is drained, stdin becomes =/dev/tty=, and that text is the first
turn. =--dump= forces the one-shot even on a terminal. That is how the TUI
is tested --- =tests/test-ai-tui.c= drives the whole path from argv through
the NDJSON parser, the event stream, the folding and the summariser against
a stub =grok=, with no network and no tty, and asserts the grouped summary
line comes out with the narration in the right order around it.

It is also the right thing to reach for in a script:

#+begin_src sh
ai-tui -p claude-code --dump "summarise the diff" --width 72 > review.txt
echo "summarise the diff" | ai-tui -p claude-code --width 72 > review.txt
#+end_src

Started without a terminal and without a prompt, =ai-tui= says so and exits
rather than starting ncurses on a pipe.

** Building
=ai-tui= needs =ncursesw=; the library itself does not. Without it the
binary is dropped from the build with a notice and its tests skip
themselves, so a machine with no terminal library still gets a green suite
for everything else.

On Fedora and its derivatives:

#+begin_src sh
ncurses-devel
#+end_src

The library is linked statically into the binary, as with =ai=, so the
installed =ai-tui= has no runtime dependency on =libai-glib=.

** Notes
- Keys arrive through the main loop (=g_unix_fd_add=), not a blocking read,
  so the provider's I/O continues while you type.
- A terminal resize re-wraps every block at the new width. That is a
  re-render, not a re-derivation: the library caches renderings per width.
- Redraws are coalesced onto an idle. A streamed reply fires a change per
  token, and redrawing on each would spend the whole turn in refresh.
- =claude-tmux= works here, but produces its answer in one piece: it reads a
  finished transcript rather than a stream, so there is nothing to show
  along the way. See the coverage matrix in [[file:events.org][the event stream]].

** MCP control and model-visible panels

=ai-tui --mcp-tools todo_write,agent_spawn,agent_status,agent_result= starts a private MCP socket and injects it into supported CLI providers. The selected host tools update the actual TODOS and AGENTS panels; system-prompt guidance tells the model to use them instead of its native harness equivalents. =--mcp-no-inject= retains external control alone. =--mcp-server= runs headlessly over stdio, and =--mcp-all-tools= explicitly grants the complete catalog, including conversation control.
