* AiResource
One markdown file with optional YAML frontmatter --- a command, a skill
or an agent. All three harnesses store all three kinds this way, which is
why one type covers them.

Construction reads a file or a buffer; there is no setter. A resource is
what was on disk at the moment it was read.

Pass =name= to =ai_resource_new_from_file()= when the path alone does not
say it --- that is how a namespaced command in =git/status.md= becomes
=git:status=. A frontmatter =name:= still wins over both.

** Properties
All read-only: =kind=, =scope=, =name=, =description=, =body=, =path=,
=origin=.

** Enumerations
| =AiResourceKind=      | =AI_RESOURCE_COMMAND=, =_SKILL=, =_AGENT=              |
| =AiResourceScope=     | =AI_RESOURCE_SCOPE_BUILTIN=, =_USER=, =_PROJECT=       |

** Notes
- *A description is one line.* Folded and literal YAML scalars are
  flattened at parse time, because every consumer of a description ---
  completion menu, listing, status bar --- has room for exactly one.
- *Malformed frontmatter is not an error.* The resource still exists,
  without metadata, and the failure is a =g_debug=. One bad file must not
  hide the others, nor abort a suite running with fatal warnings.
- *Invalid UTF-8 is an error.* Everything downstream assumes valid UTF-8;
  accepting it would only move the crash.
- Frontmatter is recognised only when the very first line is =---=. A
  =---= further down is a horizontal rule and stays in the body.
