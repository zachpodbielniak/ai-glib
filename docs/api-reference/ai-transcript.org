* AiTranscript
=AiTranscript= is the buffer: an ordered, observable list of
[[file:ai-view-block.org][AiViewBlock]]. It implements =GListModel=, which is
what a frontend watches to keep a display in step with a conversation.

It is the first =GListModel= in ai-glib, deliberately. =::items-changed=
gives insertion and removal notification in the form every GLib consumer
already knows, and a stable integer position is exactly what a frontend
mapping blocks onto its own addressing --- regions of an Emacs buffer, rows
of an ncurses pad --- needs to key on.

** Signals
| Signal            | Arguments                            | When                              |
|-------------------+--------------------------------------+-----------------------------------|
| =items-changed=   | =position=, =removed=, =added=       | a block was added or removed      |
| =block-changed=   | =position=, =AiViewBlock *block=     | a block's content changed in place |

*Both are necessary.* A block being streamed into is neither an insertion
nor a removal --- prose grows a delta at a time and a tool group's calls
change state, all without the list changing shape. A frontend watching only
=items-changed= would show the first delta of each reply and nothing after
it.

#+begin_src C
g_signal_connect (transcript, "items-changed", G_CALLBACK (on_added), self);
g_signal_connect (transcript, "block-changed", G_CALLBACK (on_changed), self);
#+end_src

Coalesce the redraws: =block-changed= fires per token during a streamed
reply, and redrawing on each would spend the whole turn in refresh.
=ai-tui= schedules one redraw per main-loop iteration with =g_idle_add()=.

** Positions move; ids do not
The position in =::block-changed= is current as of the emission. Act on it
before returning, or look the block up again --- =ai_view_block_get_id()= is
stable for the life of the process and is what a long-lived map should be
keyed on.

** Ownership
The transcript holds a reference to every block, and disconnects from a
block when it is removed. A caller holding its own reference may keep
mutating a removed block; it simply no longer reports those changes to a
transcript it is not part of.

** ai_transcript_to_text()
#+begin_src C
g_autofree gchar *text = ai_transcript_to_text (transcript, 72);
#+end_src

Renders everything at @width (0 for no wrapping) with a blank line between
blocks. This is what =ai-tui --dump= prints, what
=tests/test-ai-tui.c= asserts against, and the cheapest way to check what a
session produced without driving a display.

** ai_transcript_export()
#+begin_src C
g_autofree gchar *doc = ai_transcript_export (transcript,
                                              AI_EXPORT_FORMAT_ORG);
#+end_src

Renders the transcript as a document. =AI_EXPORT_FORMAT_TEXT= is exactly
=ai_transcript_to_text (t, 0)=, so a caller needs one entry point rather
than a special case for the format it started with.

Blocks export *expanded* whatever the display shows, via
=ai_view_block_render_expanded()= --- which neither sets the flag nor emits
=::block-changed=, so exporting a live session does not make every attached
frontend redraw. Prose blocks are read through their own text getters
rather than rendered, because the ="> "= and ="✳ ⌄"= markers are display
chrome and are not even syntax in org.

See [[file:../transcript.org][The transcript]] for the full rationale.
