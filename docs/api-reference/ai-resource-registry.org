* AiResourceRegistry
Finds the commands, skills and agents that other harnesses have already
put on disk, and decides which one wins when two claim a name.

** Properties
| Property              | Type      | Default           |
|-----------------------+-----------+-------------------|
| =working-directory=   | string    | the current one   |
| =watching=            | boolean   | =FALSE=           |

** Signals
| Signal     | Arguments | When                                     |
|------------+-----------+------------------------------------------|
| =changed=  | none      | after a scan --- once, not once per file |

A =git pull= touching thirty files produces one notification. A frontend
rebuilding a completion list wants one rebuild.

** Precedence
1. Resources added with =ai_resource_registry_add()=.
2. Every project-scope directory, in table order.
3. Every user-scope directory, in table order.

First writer wins; the rest are recorded as shadowed. The table order
within a scope is ai-glib, claude, opencode, grok --- a file written
specifically for ai-glib beats one it is borrowing.

** Notes
- A missing directory is the normal case, not an error: most of the
  search table will not exist on any given machine.
- An unreadable directory, a symlink loop, a file where a directory was
  expected: all skipped, the scan continues.
- The rescan debounce timer attaches to the *thread-default* main
  context, not the global default. A caller driving a nested loop on a
  private context would never see a global-default timer fire.
- Teaching it about another harness is one struct literal in
  =RESOURCE_SOURCES=. That table is the registration.
