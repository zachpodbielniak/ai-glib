* AiCommand, AiCommandSet, AiCommandResult
Turning a line beginning with =/= into something to do.

** AiCommand
One invocable name. Either a built-in the frontend acts on, a file that
expands to a prompt, or an agent to dispatch.

that will not read the user's home directory gets.

| =AiCommandOutcome=                 | What the caller does            |
|------------------------------------+---------------------------------|
| =AI_COMMAND_OUTCOME_NOT_A_COMMAND= | send the line as an ordinary prompt |
| =AI_COMMAND_OUTCOME_BUILTIN=       | act on =get_name()= yourself    |
| =AI_COMMAND_OUTCOME_PROMPT=        | send =get_prompt()=             |
| =AI_COMMAND_OUTCOME_AGENT=         | dispatch a subagent with =get_prompt()= |

A line that is not a command resolves rather than failing, so every line
can go through =resolve()= unconditionally. An unknown =/name= is an
error whose message names the near misses.

Mentions are *not* expanded here. That happens once, further along the
pipeline, so a =@path= in a command body and one the user typed are
treated identically and neither is expanded twice.

** Shell policy
| Value                       | Effect                                    |
|-----------------------------+-------------------------------------------|
| =AI_COMMAND_SHELL_OPT_IN=   | default --- runs only with =shell: true=  |
| =AI_COMMAND_SHELL_NEVER=    | never; overrides the file                 |
| =AI_COMMAND_SHELL_ALWAYS=   | always                                    |

The default is opt-in because scanning a directory must not be enough to
make the files in it executable. These directories are shared with other
tools, and a frontend builds its listing unprompted at startup.
