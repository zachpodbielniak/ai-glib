* Image Generation
Generate images from text prompts, optionally conditioned on reference images.

** Overview
Image generation goes through the =AiImageGenerator= interface. Three providers
implement it:

| Provider | Models                                                    | Reference images                          |
|----------+-----------------------------------------------------------+-------------------------------------------|
| OpenAI   | GPT Image 2 / 1.5 / 1, DALL-E 3 / 2                       | up to 16 (GPT Image); 1 + mask (DALL-E 2) |
| Gemini   | Nano Banana, Nano Banana 2, Nano Banana Pro, Imagen 4 / 3 | up to 14 (Nano Banana Pro); none (Imagen) |
| Grok     | Grok Imagine, Grok Imagine Quality, Grok 2 Image          | 1 (Imagine); none (Grok 2)                |

Claude and Ollama expose no image API and do not implement the interface, so
check with =AI_IS_IMAGE_GENERATOR()= before casting.

The request type, =AiImageRequest=, is a superset of every parameter these APIs
accept. No provider honours all of it; each one projects the request through the
chosen model's capability descriptor and drops what that model cannot express
(or fails, under =AI_IMAGE_VALIDATE_STRICT=). You can therefore set whatever you
like without knowing which provider will serve it. See
[[file:../api-reference/ai-image-capabilities.org][AiImageCapabilities]].

** Quick start
The synchronous form is the shortest thing that works:

#+begin_src C
#include <ai-glib.h>

int main(void)
{
    g_autoptr(AiGeminiClient) client = ai_gemini_client_new();
    g_autoptr(AiImageRequest) request = ai_image_request_new("a brass telescope");
    g_autoptr(AiImageResponse) response = NULL;
    g_autoptr(GError) error = NULL;

    response = ai_image_generator_generate_image(AI_IMAGE_GENERATOR(client),
                                                 request, NULL, &error);
    if (response == NULL)
    {
        g_printerr("%s\n", error->message);
        return 1;
    }

    ai_generated_image_save_to_file(
        ai_image_response_get_image(response, 0), "telescope.png", &error);

    return 0;
}
#+end_src

It blocks for tens of seconds. Anywhere responsiveness matters, use the async
form below instead.

** Asynchronous generation

#+begin_src C
static void
on_complete(GObject *source, GAsyncResult *result, gpointer user_data)
{
    GMainLoop *loop = user_data;
    g_autoptr(AiImageResponse) response = NULL;
    g_autoptr(GError) error = NULL;

    response = ai_image_generator_generate_image_finish(
        AI_IMAGE_GENERATOR(source), result, &error);

    if (response == NULL)
    {
        g_printerr("Error: %s\n", error->message);
        g_main_loop_quit(loop);
        return;
    }

    /* DALL-E 3 and Imagen may rewrite the prompt before generating. */
    {
        AiGeneratedImage *image = ai_image_response_get_image(response, 0);
        const gchar *revised = ai_generated_image_get_revised_prompt(image);

        if (revised != NULL)
            g_print("Revised prompt: %s\n", revised);
    }

    g_main_loop_quit(loop);
}

ai_image_generator_generate_image_async(AI_IMAGE_GENERATOR(client), request,
                                        NULL, on_complete, loop);
#+end_src

** Getting at the bytes
A provider may return inline base64 or a URL, and which one you get depends on
the model as much as on your request. =ai_generated_image_load_bytes_async()=
handles both: inline payloads short-circuit, URLs are fetched.

#+begin_src C
static void
on_bytes(GObject *source, GAsyncResult *result, gpointer user_data)
{
    g_autoptr(GBytes) bytes = NULL;
    g_autoptr(GError) error = NULL;

    bytes = ai_generated_image_load_bytes_finish(NULL, result, &error);
    if (bytes != NULL)
        g_file_set_contents("out.png", g_bytes_get_data(bytes, NULL),
                            g_bytes_get_size(bytes), NULL);
}

ai_generated_image_load_bytes_async(image, NULL, on_bytes, NULL);
#+end_src

=ai_generated_image_get_bytes()= is the synchronous shortcut, but it fails on a
URL-backed image rather than blocking on the network. The URLs providers hand
out are short-lived -- typically an hour -- so resolve them promptly rather than
storing the response and fetching later.

** Reference images
This is the capability that makes Nano Banana Pro interesting: several input
images, each doing a different job.

#+begin_src C
g_autoptr(AiGeminiClient) client = ai_gemini_client_new();
g_autoptr(AiImageRequest) request =
    ai_image_request_new("combine these into a concert poster");
g_autoptr(GError) error = NULL;

ai_image_request_set_model(request, AI_GEMINI_IMAGE_MODEL_NANO_BANANA_PRO);

ai_image_request_add_reference_file(request, "palette.png", "style", &error);
ai_image_request_add_reference_file(request, "macaw.jpg", "subject", &error);
ai_image_request_add_reference_file(request, "venue.jpg", "background", &error);
#+end_src

Order is preserved and significant. The roles matter because the wire formats
carry references as a bare ordered list with no field saying what each is for --
ai-glib folds the labels into the prompt text, which is the only channel the
model reads. Unlabelled references are simply passed through in order.

Asking for more references than a model accepts is an error even in lenient
mode: silently dropping one would change the image in a way you could not see.

** Editing and variations
Set the operation. On OpenAI this routes to =/v1/images/edits= or
=/v1/images/variations= as a multipart post; on Gemini everything goes through
the same chat-shaped endpoint.

#+begin_src C
g_autoptr(AiImageRequest) request =
    ai_image_request_new("replace the sky with a storm");
g_autoptr(AiImage) mask = ai_image_new_from_file("sky-mask.png", NULL);

ai_image_request_set_operation(request, AI_IMAGE_OPERATION_EDIT);
ai_image_request_add_reference_file(request, "photo.png", NULL, NULL);
ai_image_request_set_mask(request, mask);
ai_image_request_set_input_fidelity(request, AI_IMAGE_FIDELITY_HIGH);
#+end_src

The transparent areas of the mask are the ones regenerated.
=AI_IMAGE_FIDELITY_HIGH= is what you want when a face or a logo has to survive
the round trip recognisably.

** Geometry
The two families disagree about how to express size, so ai-glib carries both and
lets the capability check sort it out.

#+begin_src C
/* Gemini: a ratio plus a resolution tier. */
ai_image_request_set_aspect_ratio(request, "16:9");
ai_image_request_set_resolution(request, AI_IMAGE_RESOLUTION_4K);

/* OpenAI: explicit pixel dimensions. */
ai_image_request_set_custom_size(request, "1536x1024");
#+end_src

Setting one does not disturb the other, so a request can be aimed at either
without the caller knowing which is in play.

** Transparency and output encoding

#+begin_src C
ai_image_request_set_background(request, AI_IMAGE_BACKGROUND_TRANSPARENT);
ai_image_request_set_output_format(request, AI_IMAGE_FORMAT_WEBP);
ai_image_request_set_output_compression(request, 80);
#+end_src

Transparency needs a format with an alpha channel. Pairing it with
=AI_IMAGE_FORMAT_JPEG= is rejected rather than silently producing an opaque
image.

** Reproducibility

#+begin_src C
ai_image_request_set_seed(request, 42);
ai_image_request_set_negative_prompt(request, "text, watermark, signature");
#+end_src

Reproducibility is best-effort, and only holds while the model and the rest of
the parameters are fixed.

** Batches and progress

#+begin_src C
ai_image_request_set_count(request, 4);

g_signal_connect(client, "image-progress", G_CALLBACK(on_progress), NULL);
#+end_src

A count above the model's maximum is clamped rather than rejected, since getting
fewer images than asked for is visible in the response.

** Anything not modelled here
New API parameters appear faster than a binding can track them, so there is an
escape hatch. Extras are spliced verbatim into the request body and applied
last, so they override any modelled parameter serialising to the same member.

#+begin_src C
ai_image_request_set_extra_string(request, "brand_new_param", "value");
ai_image_request_set_extra(request, "count_of_things", g_variant_new_int32(3));
#+end_src

Nothing is validated: an unknown key reaches the provider exactly as written,
and whatever the provider says about it comes back as the request error.

** Checking before you send

#+begin_src C
const AiImageModelInfo *info =
    ai_image_generator_get_model_info(AI_IMAGE_GENERATOR(client), NULL);

if (!ai_image_model_info_supports(info, AI_IMAGE_CAP_TRANSPARENCY))
    g_print("this model cannot do transparent backgrounds\n");
#+end_src

Or let it fail loudly instead of degrading:

#+begin_src C
if (!ai_image_request_validate(request, info, AI_IMAGE_VALIDATE_STRICT, &error))
    g_printerr("%s\n", error->message);
#+end_src

** Errors
Failures arrive in the =AI_ERROR= domain with the provider's own explanation
quoted into the message, which is usually the useful part. Notable cases:

| Code                        | Typical cause                                                            |
|-----------------------------+--------------------------------------------------------------------------|
| =AI_ERROR_INVALID_API_KEY=  | missing or wrong key                                                     |
| =AI_ERROR_RATE_LIMITED=     | 429; retried with backoff before surfacing                               |
| =AI_ERROR_INVALID_REQUEST=  | content-policy refusal, or an unsupported option under strict validation |
| =AI_ERROR_INVALID_RESPONSE= | the model answered with text instead of an image                         |

Transient failures (429, 5xx, transport errors) are retried automatically with
exponential backoff, honouring =Retry-After=. The budget comes from
=ai_config_set_max_retries()=.

** From the command line
Everything above is reachable from the =ai= binary; see [[file:../cli.org][the CLI documentation]].

#+begin_src sh
ai --image-gen -p gemini -m gemini-3-pro-image-preview \
   --ref palette.png --ref-role style \
   --ref macaw.jpg   --ref-role subject \
   --aspect 16:9 --resolution 2k -o poster.png \
   "combine these into a concert poster"
#+end_src
