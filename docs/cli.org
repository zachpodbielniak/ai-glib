* The =ai= CLI
=ai= is a small command-line front-end for ai-glib. It lets you drive every
provider by hand --- pick a provider and model, send a prompt (from an
argument or stdin), and print the reply to stdout. It is the easiest way to
exercise the providers, and in particular to verify the Ollama-as-transport
rewrite for the Claude Code providers, outside the larger integrations.

The binary is built as part of =make= (landing at =build/<type>/bin/ai=) and
installed into =$(PREFIX)/bin= by =make install=.

** Synopsis
#+begin_example
ai [OPTIONS] [PROMPT]
echo "PROMPT" | ai [OPTIONS]
#+end_example

The prompt comes from the positional argument(s) if present, otherwise from
stdin (when stdin is not a terminal). The response is written to *stdout*;
diagnostics, notes and usage go to *stderr*, so stdout stays clean for
piping.

** Options
| Option                  | Description                                                        |
|-------------------------+--------------------------------------------------------------------|
| =-p=, =--provider NAME= | claude, openai, gemini, grok, ollama, claude-code, claude-tmux, opencode, grok-build, antigravity (agy), cursor, codex-cli (default: =$AI_PROVIDER= or =claude=) |
| =-m=, =--model ID=      | Model id (default: provider default). =ollama/<id>= on the Claude Code providers selects the Ollama transport |
| =-s=, =--system TEXT=   | System prompt                                                      |
| =--effort LEVEL=        | Effort / thinking level (CLI providers)                            |
| =--max-tokens N=        | Max output tokens (default: 4096)                                  |
| =--temperature F=       | Sampling temperature (HTTP providers)                             |
| =--stream=              | Stream the response as it arrives (providers that support it)      |
| =--skip-permissions=    | Bypass tool-use approval (every CLI provider)                      |
| =-c=, =--continue=      | Continue this directory's most recent session (CLI providers)      |
| =--set PROP=VALUE=      | Set any provider property; repeatable (see below)                  |
| =--dry-run=             | Print the command that would be spawned; do not run it             |
| =--list-providers=      | List known provider names and exit                                 |
| =-i=, =--interactive=   | Interactive multi-turn REPL (keeps history)                        |
| =-v=, =--version=       | Print version and exit                                             |

** Examples
List the providers:
#+begin_example
$ ai --list-providers
Providers:
  claude         HTTP
  ...
  claude-code    CLI   (model "ollama/<name>" => ollama launch claude)
  claude-tmux    CLI   (model "ollama/<name>" => ollama launch claude)
  opencode       CLI
  grok-build     CLI
  antigravity    CLI
  cursor         CLI
  codex-cli      CLI
#+end_example

A one-shot chat (HTTP provider):
#+begin_example
$ ai -p claude -m claude-sonnet-5 "Say hi in one word"
#+end_example

Stream from stdin:
#+begin_example
$ echo "Write a haiku about C" | ai -p openai --stream
#+end_example

Verify the Ollama transport without running anything (=--dry-run=):
#+begin_example
$ ai -p claude-code -m ollama/glm-5.2:cloud --dry-run "hi"
/usr/bin/ollama launch claude --model glm-5.2:cloud -- --print --output-format json ...

$ ai -p claude-tmux -m ollama/glm-5.2:cloud --dry-run "hi"
tmux -L ai-glib new-session -d -s ai-glib-dry-run -c <cwd> -- ollama launch claude --model glm-5.2:cloud -- --session-id <session-id> --settings <settings.json>

$ ai -p claude-code -m sonnet --dry-run "hi"
/path/to/claude --print --output-format json --model sonnet ...

$ ai -p grok-build -m grok-4.6 --effort low --dry-run "hi"
/path/to/grok --prompt-file /dev/stdin --output-format json --model grok-4.6 --verbatim --reasoning-effort low

$ ai -p agy --dry-run "hi"
/path/to/agy --input-format stream-json --output-format stream-json --print-timeout 30m --model gemini-3.7-flash-high --disable-slash-commands --effort medium

$ ai -p cursor --dry-run "hi"
/path/to/cursor-agent --print --output-format json --model auto
#+end_example

The =grok-build= prompt never appears in argv: it is piped on stdin and
read back through =--prompt-file /dev/stdin=. The =antigravity= / =agy=
prompt is likewise piped, as one stream-json user event, because
=agy --print= consumes the next argv word. =cursor= also pipes the prompt
on stdin; its =--print= is a boolean, so flags after it are safe, but a
long conversation would still hit =MAX_ARG_STRLEN= as a positional.

** Continuing a session (=--continue=)
=-c= picks up where this directory left off, rather than starting a new
session:

#+begin_example
$ ai -p claude-code "start refactoring the parser"
$ ai -p claude-code -c "now update the tests"
#+end_example

It works for every CLI provider, each in its own spelling: =--continue= for
claude-code, opencode, grok-build, antigravity and cursor. claude-tmux resolves the directory's
newest transcript and resumes it *by id* instead — everything in that
provider is keyed by session id, and claude's own =--continue= never
reports which session it picked.

- A known session id wins over =--continue=: the two name different
  sessions, and quietly preferring the wrong one is worse than either. Set
  one with =--set session-id=<id>=.
- =--set session-persistence=false= asks for a fresh session every time and
  therefore suppresses it.
- With nothing to continue, claude-tmux starts a fresh session rather than
  failing; the other three leave that to the CLI.
- HTTP providers have no sessions. They say so on stderr rather than
  accepting the flag and ignoring it.

** Setting provider properties (=--set=)
The flags above cover what every provider has in common. Everything else --- a
sandbox profile, a turn budget, an MCP config path, a session to resume --- is a
GObject property on the provider, and =--set= reaches all of them without a
flag per provider per knob:

#+begin_example
$ ai -p grok-build --set sandbox=workspace --set max-turns=20 \
     --set permission-mode=acceptEdits "refactor the parser"
#+end_example

- Repeatable; applied left to right, *after* the dedicated flags, so
  =--set model=...= overrides =-m=.
- A bare =--set NAME= sets a boolean property to true:
  =--set disable-web-search=. Booleans also accept
  =true/false=, =yes/no=, =on/off=, =1/0=.
- Strings, integers, doubles, booleans and enums are supported. A value that
  does not parse is an error rather than a silent zero --- otherwise the run
  proceeds without the bound you asked for.
- Read-only properties (=total-cost=) are refused.
- Name a property the provider does not have and it prints the ones it does:

#+begin_example
$ ai -p grok-build --set nope=1 "hi"
ai: no property 'nope' on this provider
ai: AiGrokBuildClient accepts:
  model                    gchararray
  system-prompt            gchararray
  working-directory        gchararray
  session-id               gchararray
  effort-level             gchararray
  skip-permissions         gboolean
  permission-mode          gchararray
  allowed-tools            gchararray
  sandbox                  gchararray
  max-turns                gint
  ...
#+end_example

Pair it with =--dry-run= to confirm what a setting actually produces:

#+begin_example
$ ai -p grok-build --set sandbox=workspace --set max-turns=20 --dry-run "hi"
/path/to/grok --prompt-file /dev/stdin --output-format json --model grok-4.6 \
  --sandbox workspace --max-turns 20 --verbatim --reasoning-effort medium
#+end_example

An interactive session:
#+begin_example
$ ai -p claude-code -i
ai interactive (provider=claude-code). Ctrl-D to exit.
> hello
...
#+end_example

** Image generation
=--image-gen= switches the CLI from chatting to generating an image, written to
a file rather than printed. All the image options below are listed by
=ai --help=: a long complete help beats a short one that omits most of the mode
it is documenting.

*** Model discovery
=--list-image-models= prints every image model with its limits and capabilities,
generated from the providers' own tables rather than a hand-maintained list:

#+begin_src sh
ai --list-image-models            # all providers
ai --list-image-models -p gemini  # one provider
#+end_src

#+begin_example
MODEL                              PROVIDER   REFS MAX-N  CAPABILITIES
gemini-3-pro-image-preview         gemini       14     4  reference-images,multi-reference,seed,...
                                   Multi-reference conditioning, up to 4K
#+end_example

*** Options
| Option                   | Meaning                                                     |
|--------------------------+-------------------------------------------------------------|
| =-I, --image-gen=        | generate an image instead of text                            |
| =-o, --image-out=FILE=   | output path; default auto-numbered =output-0000.png=         |
| =--image-op=OP=          | =generate=, =edit=, =variation= or =upscale=                 |
| =--ref=FILE=             | reference image; repeatable for multi-image conditioning     |
| =--ref-role=ROLE=        | label for the preceding =--ref=, e.g. =style=                |
| =--ref-style=ROLE=       | alias for =--ref-role=                                       |
| =--mask=FILE=            | edit mask; transparent areas are regenerated                 |
| =--aspect=RATIO=         | e.g. =16:9= (Gemini, Imagen)                                 |
| =--size=WxH=             | e.g. =1024x1024= (OpenAI)                                    |
| =--resolution=TIER=      | =1k=, =2k=, =4k=                                             |
| =-n, --count=N=          | how many images                                              |
| =--quality=LEVEL=        | translated to whichever vocabulary the model accepts         |
| =--style=STYLE=          | =vivid=, =natural=, or a provider-specific preset            |
| =--background=MODE=      | =transparent= needs a format with alpha                      |
| =--format=FMT=           | =png=, =jpeg=, =webp=                                        |
| =--compression=N=        | 0-100, lossy formats                                         |
| =--negative=TEXT=        | what to keep out (Imagen)                                    |
| =--seed=N=               | reproducible sampling                                        |
| =--guidance=F=, =--steps=N=, =--strength=F= | sampler controls                          |
| =--moderation=LEVEL=     | =auto=, =low=, =none=                                        |
| =--person-generation=MODE= | =dont_allow=, =allow_adult=, =allow_all= (Imagen)          |
| =--language=LANG=        | prompt language hint (Imagen)                                |
| =--input-fidelity=LEVEL= | how closely an edit preserves its input                      |
| =--no-watermark=         | where the provider allows it                                 |
| =--image-url=            | request a URL rather than inline bytes; still saved locally  |
| =--image-extra=KEY=VALUE= | passed straight through; repeatable                         |
| =--strict=               | fail on an unsupported option instead of dropping it         |

*** Examples

#+begin_src sh
# Simplest case.
ai --image-gen -o sunset.png "a sunset over mountains"

# Gemini geometry: ratio plus resolution tier.
ai --image-gen -p gemini --aspect 16:9 --resolution 2k \
   "a brass telescope on a wooden desk"

# Multi-reference conditioning, each input given a job.
ai --image-gen -p gemini -m gemini-3-pro-image-preview \
   --ref palette.png --ref-role style \
   --ref macaw.jpg   --ref-role subject \
   -o poster.png "combine these into a concert poster"

# A transparent WebP icon.
ai --image-gen -p openai -m gpt-image-2 \
   --background transparent --format webp -o icon.webp \
   "a minimal gear icon"

# Masked edit.
ai --image-gen --image-op edit --ref photo.png --mask sky.png \
   "replace the sky with a storm"

# Four reproducible variations.
ai --image-gen -n 4 --seed 42 --negative "text, watermark" \
   "abstract shapes in blue"
#+end_src

The path of each image written is printed on stdout, one per line, so the
command composes:

#+begin_src sh
ai --image-gen -o out.png "a cat" | xargs -r feh
#+end_src

A revised prompt, when the model rewrites one, goes to stderr so it does not
pollute that list.

*** Behaviour worth knowing
- Options a model cannot honour are dropped, and the request proceeds. Pass
  =--strict= to fail instead, which is what you want in a script.
- Reference images beyond a model's limit are always an error, never truncated.
- With =-n= above 1 and an explicit =--image-out=, the index is inserted before
  the extension so a batch does not overwrite itself.
- API keys come from the environment: =ANTHROPIC_API_KEY=, =OPENAI_API_KEY=,
  =GEMINI_API_KEY=, =XAI_API_KEY=. Base URLs can be overridden with
  =OPENAI_BASE_URL=, =GEMINI_BASE_URL=, =XAI_BASE_URL=, =ANTHROPIC_BASE_URL=.

** Notes
- =--dry-run= prints the real argv for *every* CLI provider — claude-code,
  claude-tmux, opencode, grok-build, antigravity, cursor — with the executable resolved and, for
  the claude providers, the Ollama transport applied. It goes through the
  =AiCliClient= vtable rather than a branch per provider, so a new CLI
  provider gets it for free. HTTP providers print a short summary instead,
  since they spawn nothing.
- =--skip-permissions= applies to every CLI provider that has the concept,
  each in its own spelling: =--dangerously-skip-permissions= for the claude
  and antigravity providers, =--auto= for opencode, =--permission-mode bypassPermissions=
  for grok-build, =--force= for cursor.
- =--effort= maps to =--reasoning-effort= for =grok-build=, which accepts
  =low=, =medium=, =high= and =xhigh=; =max= is folded onto =xhigh=. For
  =antigravity= it is =--effort= (=low=, =medium=, =high=); =xhigh= and
  =max= fold onto =high=. Cursor bakes effort into the model id; use
  the =model-params= property for bracket overrides rather than =--effort=.
- For the Ollama transport the =claude= binary must be installed and on
  =$PATH= (=ollama launch claude= execs it); the launcher path may be
  overridden with =OLLAMA_PATH=.
- HTTP providers read their API keys from the usual environment variables
  (see [[file:configuration.org][Configuration]]).

** Commands and mentions
=ai= runs the same input pipeline =ai-tui= does, so a prompt may name a
command or reference files:

#+begin_src bash
ai '/skill-gtest-scaffold src/core/ai-event.c'
#+end_src

#+begin_src bash
ai 'what does this do? @src/core/ai-event.c'
#+end_src

The command is looked up in the same directories every other harness
uses --- see [[file:harness.org][the harness layer]] --- and =@path=
mentions are appended to the prompt.

Three cases where it does not apply:

- *CLI providers.* claude-code, opencode, grok, antigravity and cursor resolve both
  themselves, so the prompt goes through untouched.
- *=--dry-run=.* The point there is the command line, not the filesystem;
  expanding first would put a file into the argv dump.
- *=--no-expand=.* Turns it off outright.

A built-in like =/clear= acts on a session, and a one-shot run has none,
so =ai= says so and points at =ai-tui=. An unknown =/name= is an error
rather than a prompt beginning with a slash --- use =--no-expand= if you
meant it literally.

** Sandbox policies
=--sandbox MODE= sets the selected provider's native =sandbox= property.
It can also be set with =--set sandbox=MODE=. Unsupported providers reject
=--sandbox= instead of silently ignoring it.

| Provider | Values | Implementation |
|----------+--------+----------------|
| =codex-cli= | =read-only=, =workspace-write=, =danger-full-access= | =codex exec --sandbox=; defaults to read-only |
| =claude-code=, =claude-tmux= | =enabled=, =disabled= | Merge native Bash sandbox settings with existing settings/hooks |
| =grok-build= | Native Grok profile, e.g. =workspace= | Existing =--sandbox PROFILE= support |
| =cursor= | =enabled=, =disabled= | Existing =--sandbox MODE= support |
| =antigravity= | =enabled= / =true=, =disabled= / =false= | Boolean =--sandbox= flag |

Claude's =enabled= sets =sandbox.enabled=true=,
=allowUnsandboxedCommands=false= and =failIfUnavailable=true=. Existing
filesystem/network rules and excluded commands are retained. This is Claude's
native Bash sandbox, whose coverage and platform support are defined by
[[https://code.claude.com/docs/en/sandboxing][Claude's sandbox documentation]]; permission approval and sandboxing are
separate controls. Leaving the property unset preserves existing settings.
OpenCode and HTTP providers have no sandbox property; OpenCode's permission
controls do not supply an OS sandbox.

#+begin_src sh
ai -p codex-cli --sandbox workspace-write --set additional-directories=/tmp/build "Fix tests"
ai -p claude-code --sandbox enabled "Run the checks"
ai -p grok-build --sandbox workspace "Inspect the project"
ai -p cursor --sandbox enabled "Inspect the project"
ai -p antigravity --sandbox enabled "Inspect the project"
#+end_src

See [[file:providers/codex-cli.org][Codex CLI]] for models, session behavior and provider properties.

* User-configured OpenAI-compatible servers

Use =openai-compatible= (alias =http=) with your own API root, token and
model ID. See [[file:providers/openai-compatible.org][the OpenAI-compatible provider guide]] for
configuration, supported APIs, examples and compatibility limits.
